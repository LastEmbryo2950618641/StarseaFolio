# 知识图谱测试集与效果评测方案

本文基于当前代码及在线公开资料整理。已实现隔离后端评测运行器、确定性评分与 120 题合成试验集；真实模型运行结果另行保存，不能把测试代码通过当作图谱质量通过。下文 180 题规模及未实现的指标仍是后续建议。

## 1. 评测对象与现有缺口

Worldseed 的图治理维护可修订的知识图谱，并通过检索投影和 Source 返回事实及原文。应分别评测事实入图、证据检索、最终回答与修订可靠性，不能仅凭节点数量、流程完成或模型自评认定图谱有效。

当前可复用的实现：

| 实现 | 已提供的能力 | 仍需独立验证 |
| --- | --- | --- |
| `apps/backend/src/application/turns/verification-probe-coordinator.ts` | 应用真实执行探针，要求每个执行结果被评估一次 | 评估结论是否与独立标准事实一致 |
| `apps/backend/acceptance/lib/graph-audit.mjs` | 探针覆盖、时序声明在多个阶段中的覆盖 | 声明本身是否正确、是否遗漏正文事实 |
| `scripts/acceptance/lib/graph-cost-ab-audit.mjs` | 成对输入的 Token、耗时及流程检查 | 同等成本下的事实正确性与检索收益 |
| `apps/backend/src/infrastructure/sqlite/repositories/sqlite-retrieval-repository.ts` | 检索投影、FTS、BM25、短文本及子串匹配 | 别名、中文短名字、同义改写的召回 |
| `apps/backend/src/bootstrap/backend-facade.ts` | `world.query`、`graph.neighborhood` | 独立查询上下文、历史快照和证据评分的评测适配 |
| `docs/full-chain-validation.md` | 已提出真实长跑、远期召回、历史与世界线验收要求 | 需要真实运行证据及人工复核的答案，文档要求不代表已通过 |

特别注意：当前检索仓库中的 `semanticText` 经由词法检索使用，不能仅凭字段名认定具有向量语义召回能力。图谱拓扑由治理生成，同一事实可以有多种合理表示，不应强求与某套标准节点 UUID、节点数量或三元组结构完全相同。

## 2. 网上方法及其适用范围

| 来源 | 公开方法 | 本项目采用方式 |
| --- | --- | --- |
| [Ragas 测试集生成](https://docs.ragas.io/en/stable/concepts/test_data_generation/rag/) | 单跳/多跳、具体/抽象问题；从材料形成场景并生成问题、参考上下文及答案 | 建立问题类型矩阵，辅助生成样本，再独立复核 |
| [Ragas Context Recall](https://docs.ragas.io/en/stable/concepts/metrics/available_metrics/context_recall/) | 用参考答案声明或参考上下文 ID 衡量召回 | 利用 Source 定位信息核对是否找全所需证据 |
| [Ragas Faithfulness](https://docs.ragas.io/en/stable/concepts/metrics/available_metrics/faithfulness/) | 回答声明被检索证据支持的比例 | 检查回答是否编造；另行检查证据是否过期或错误 |
| [HotpotQA](https://hotpotqa.github.io/) | 多跳问答，标注支持事实，并联合评价答案和支持事实 | 多跳题必须同时答对并找到完整证据链 |
| [LongMemEval](https://github.com/xiaowu0162/LongMemEval) | 信息提取、跨会话推理、知识更新、时间推理、拒答五类能力；500 道问题 | 把会话换成章节，重点测跨章更新、历史与未知事实 |
| [CRAG](https://github.com/facebookresearch/CRAG) | 动态信息、不同难度和问题类型；区分正确、缺答与错误 | 对自信编造给予负分，同时单独统计未知题正确拒答率 |
| [Microsoft GraphRAG](https://microsoft.github.io/graphrag/query/overview/) | 区分局部实体查询和全局主题查询，并提供基本检索比较 | 分开评价局部事实与跨章概括；不假定本项目已有社区报告或相同架构 |
| [W3C SHACL](https://www.w3.org/TR/shacl/) | RDF 图结构约束验证 | 借鉴结构校验与语义评测分层；本项目无需因此迁移到 RDF 或引入 SHACL |

上述资料直接在线查阅。建议借鉴方法、使用自有小说语料，不直接搬用公开数据集。若实际复用，需另核对许可；例如 CRAG 标注为 CC BY-NC 4.0。

## 3. 测试集如何构建

### 3.1 从原文建立独立标准

1. 冻结原文章节、设定及其版本，保存文件摘要、发布顺序、世界线和快照清单。
2. 从原文人工标注事实、证据片段、有效时间、说话人/认知主体、确定性；允许模型辅助提出候选，但需人工复核。
3. 由这些事实生成问题、参考答案及必要证据组。构造别名、同义改写、干扰人物和跨章问题。
4. 对无答案题明确标记“资料未说明”，不能把缺少记录等同于事实为假；区分传闻、梦境、计划与既成事实。
5. 标注人员复核答案及证据是否完整；多解题接受多个有效答案或证据组合。
6. 按整本书/独立故事线划分开发集与保留测试集，不能把同一事实的改写题随机分散到两侧。调参前冻结保留集。

不能只根据系统已经生成的图谱出题，否则漏入图的事实不会被问到。图谱可以帮助补充难题，原文才是事实标准。评测标准答案和隐藏快照不得进入被测模型上下文。

### 3.2 第一批规模建议

使用 3 本隔离测试书，每本 8 至 10 章，建立 180 道经人工核对的问题，先定位问题并形成基线。下表按主要类型计数，别名、时间和证据长度可以作为交叉标签。

| 主要类型 | 数量 | 核心场景 |
| --- | --- | --- |
| 单跳事实 | 25 | 谁、地点、物品、关系、数量 |
| 别名与同义表达 | 25 | 称号、同名不同人、1 至 2 字人名、换一种问法 |
| 跨章多跳 | 30 | 2 至 4 条事实共同决定答案；不能只找中间一条 |
| 当前与历史状态 | 30 | 转交、迁移、关系变化、时间顺序、过去与现在 |
| 原文证据 | 20 | 对白精确引用、上下文边界、指代归属 |
| 跨章概括 | 15 | 事件链、角色变化；接受有证据的多种表述 |
| 无答案与错误前提 | 20 | 未说明、假设性前提、传闻当事实、诱导编造 |
| 修订与恢复 | 15 | 替换正文、重试、归档、压缩、世界线切换后的事实一致性 |

基础集稳定后，再扩展到 20、50、100 章；记录图规模、证据距离及干扰量。规模扩大时保留同一批早期问题，才能判断远期事实是否退化。

### 3.3 样本格式

以下展示扩展标注格式，不是当前执行器的完整接口契约；实际版本 1 使用包含 `books`、`chapters`、`cases` 的 JSON，详见 `scripts/acceptance/fixtures/knowledge-graph/README.md`。虚构故事中，第 1 章叶青交给陆尘铜钥匙，第 2 章陆尘把它交给韩舟。

```json
{
  "case_id": "key-current-002",
  "book_id": "fixture-a",
  "worldline_id": "main",
  "snapshot_id": "after-chapter-02-v1",
  "source_manifest_digest": "<sha256-of-frozen-source-manifest>",
  "task_type": "state_update",
  "tags": ["current_state", "cross_chapter"],
  "question": "读到第二章结束，铜钥匙由谁持有？",
  "answerable": true,
  "reference_answers": ["韩舟"],
  "reference_claims": ["第二章结束时铜钥匙由韩舟持有"],
  "evidence_sets_any_of": [
    {
      "all_of": [
        {
          "source_key": "chapter-02-v1",
          "content_digest": "<sha256-of-source>",
          "span": { "start": 0, "end": 13, "unit": "unicode_code_point", "end_exclusive": true },
          "quote": "陆尘把铜钥匙递给韩舟保管。"
        }
      ]
    }
  ],
  "forbidden_claims": ["钥匙仍由陆尘持有"]
}
```

这里 `span` 相对于所引冻结 Source 单元，示例单元只有这句话。实际标注器需自动校验摘要及片段是否一致。标准证据使用稳定的原文版本与片段定位，不使用某次运行随机生成的图节点 ID；执行时映射到运行时 Source 和 Evidence。

多跳题的一组 `all_of` 保存全部必要片段；`evidence_sets_any_of` 允许不同但完整的证明路径。未来才能知道的事实不允许用于早期快照题。故事内时间与文档修订时间应分别记录，不能混为一个章节序号。

## 4. 怎样判断效果

| 层次 | 指标 | 解释 |
| --- | --- | --- |
| 结构与事务 | 悬空引用、证据摘要有效性、pending 泄漏、跨世界线污染、重复提交 | 用代码与存储结果直接检查，不交给模型自评 |
| 事实表示 | 已核对事实的准确率/召回率、别名合并正确性、状态更新正确率 | 人工对齐语义；区分图结构承载与只能回到 Source 查到 |
| 检索 | Evidence Recall@k、Precision@k、多跳完整证据命中率 | 按标准片段映射去重，不能用节点数量替代证据数量 |
| 排序 | MRR 或 nDCG@k | 有相关性标注时评价正确证据是否排前；多跳仍需另测完整性 |
| 回答 | 答案正确率、声明级 Precision/Recall/F1、证据支持率 | 答对但证据错误、证据正确但答案错，分别计数 |
| 引用 | 定位有效率、引用支持率、必要声明引用覆盖率 | 原文可打开不等于能证明这句话 |
| 未知题 | 未知题正确拒答率、有答案题误拒率、无依据断言率 | 防止全部回答“不知道”获得虚假高分 |
| 性能 | 建图与查询 p50/p95 耗时、供应商 Token、费用、修复/失败次数 | 分开报告建图、查找、生成；重试耗费也算入 |

计算口径：

- Evidence Recall@k = 前 k 个去重证据覆盖的必要标准片段数 / 必要标准片段总数。存在多组合法证明时，按覆盖最好的合法组计算，同时报告完整组命中率；标准只要求某段中的关键句时，不强求整个段落字节相等。
- 多跳完整命中率 = 至少覆盖一组全部必要证据的问题数 / 多跳问题总数。
- 证据支持率 = 被返回证据支持的回答声明数 / 所有可核对回答声明数。证据支持率不等于事实正确率：旧状态也可能有真实原文支持。
- 答案与证据联合通过 = 答案正确、证据完整、符合指定版本与时间、没有禁止断言四者同时满足。

事实准确率需明确抽样与分母：对预定义事实清单计算召回；对被测系统输出的事实做全量或记录抽样方法的精度审核。不能只检查预期事实而宣称没有额外编造。

主观概括可用独立模型按评分规则辅助评价，但需保存裁判模型/版本、输入和逐项理由，校准人工一致率。状态、身份、引用、隔离、原文匹配优先使用确定性评分；有争议的题人工裁决。

## 5. 如何证明是图谱带来的收益

同一批问题、相同原文快照和回答模型，比较：

| 组别 | 输入/检索方式 | 用途 |
| --- | --- | --- |
| A | 无检索、无历史对话，仅给问题 | 排查依赖常识或泄漏答案 |
| B | 原文词法检索 + Source | 建立实际可用的基础检索基线 |
| C | 图谱检索/遍历 + Source | 测试正式能力与相对 B 的增益 |
| D | 人工标准证据 + 回答模型 | 定位回答能力上限；不能算正式检索成绩 |

B/C 使用相同返回上下文 Token 预算，并公开各自检索轮次、候选上限和总成本。D 是诊断参考，可能包含更完整证据，应明确记录预算差异。图谱相对收益主要看 C-B 的答案/证据联合正确率及成本差异，尤其是跨章、更新与多跳题。

另设可控小图的检索层测试，区分入图错误、检索错误与回答错误。直接构造数据库只适合该层测试，不能替代原文经过正式图治理和提交的全流程测试。

运行成对问题，固定配置并保存随机性设置；对模型生成和裁判重复抽样，对关键结论报告按书分组的区间或至少逐书结果。第一批仅 3 本书，不能用小样本高分宣称对所有题材有效。区分冷热缓存，并将建图成本按查询次数展示摊销，不能只比较查询速度。

## 6. 本项目执行注意事项

1. 在隔离项目中通过正式发布流程产生 Source、图修订与已提交版本。标准答案存放在评测侧，不进入被测工作区。
2. 检索测试直接复用 repository 能力捕获候选证据；问答测试通过正式 `world.query` 收集 `answerMarkdown`、Evidence、usage 与运行日志。仅看聊天文本不足以计算证据召回。
3. `world.query` 当前入口存在固定 `chapterSequence: 1` 的调用参数，不能据此承诺支持任意历史截止点。时间题优先恢复冻结快照并在查询中明确时点，历史过滤能力需另外核对或补充。
4. 设置 `allowWorkspaceChapterReads: false`，同时审计实际 read requests，确认只能通过允许的图谱与 Source 路径取证。保留合法的 Source 原文回查，不能把它也禁止。
5. 每道题需隔离查询上下文，并审计实际发送的模型消息，确保旧讨论、前题答案和完整章节没有绕过检索进入上下文。当前执行器在独立数据库中隐藏先前非系统模型消息，再审计实际传入适配器的消息和读取证据；单设读取开关不足以证明这一点。
6. 另做端到端真实产品路径抽查，使用 DOM 驱动界面；仓库层测试和后端查询成绩分别报告，不能冒充界面流程通过。
7. 正文替换、归档、容量治理、上下文压缩、重启、分支切换前后重跑相同问题。声明被推翻与历史原文仍存在可以同时成立，应保留版本语义。
8. 每次保存代码提交及未提交差异摘要、模型版本、原文清单、图快照、问题集版本、检索轨迹、回答、裁判结果、供应商用量和失败原因。失败案例必须可重放。

首轮先建立分项基线，再制定数值门槛。跨世界线/pending 泄漏、失效证据引用和未完成提交被误当正式事实属于必须逐案阻断的问题，不应被平均分掩盖。暂不预设一个综合分来覆盖所有缺陷。

## 7. 建议交付顺序

1. 标注规范、隔离短书、原文清单和少量人工核对示例；确认时间与证据粒度。
2. 实现独立评测适配器与确定性评分，扩充至 180 题并冻结保留集。
3. 执行 B/C/D 比较，按“入图 / 召回 / 回答 / 隔离”定位失败，保留 A 作为泄漏诊断。
4. 修复主要失败类型后扩展长篇及治理前后回归，再结合已有成本 A/B 和全链路验收。

现已具备独立于运行时图谱的合成问题与证据标准、联合评分及真实调用入口。标准仍待人工复核，已完成 6 题的 B/C 试跑，完整 B/C/D 对照尚未完成，不能据此给出“知识图谱效果良好”或“优于词法检索”的结论。

## 8. 已实现的试验入口

语料包括 3 本独立短书、24 章、120 题，其中 102 道可回答题、18 道未知题；共有 105 组合法证明、187 个组内去重必要证据要求。两本为开发集，一本为保留集。标注状态为 `model_authored_pending_human_review`，结构校验不代表人工金标或语义正确。

从仓库根目录执行：

```powershell
corepack pnpm verify:knowledge-graph:validate
corepack pnpm exec vitest run scripts/acceptance/test/knowledge-graph-evaluation.test.mjs scripts/acceptance/test/knowledge-graph-trace.test.mjs scripts/acceptance/test/knowledge-graph-compare.test.mjs

# 需要已构建的后端、运行中的桌面应用及其 CDP 端口和已配置模型。
corepack pnpm --filter @worldseed/backend build
$env:WORLDSEED_ACCEPTANCE_REAL='1'
corepack pnpm verify:knowledge-graph --mode graph --desktop-user-data 'C:/Users/liuqi/AppData/Roaming/@worldseed/desktop' --book reed-canal --cases reed-canal-alias,reed-canal-gauge,reed-canal-password,reed-canal-ferry-steward,reed-canal-alias-water,reed-canal-unknown-future --limit 6
```

可通过 `--cdp`、`--timeout`、`--output`、`--benchmark` 指定配置；默认 CDP 为 `http://127.0.0.1:9333`，单轮超时 300 秒。`--mode source-only` 跳过图治理，只保留同样的 Source 与词法索引，使用相同查询编排器，作为 B 组。默认仅选择首本开发书的前 6 题；明确指定 `--book` 和 `--limit 40` 才会选择一本书的全部 40 题。真实调用会消耗当前模型额度。

执行器优先使用环境变量 `WORLDSEED_BENCHMARK_API_KEY`，否则使用当前模型配置或桌面应用保存的凭据。凭据只在进程内传递，不写入报告。

两组执行完后，可比较保存的报告，无需再次调用模型：

```powershell
corepack pnpm verify:knowledge-graph:compare '<B组目录>/report.json' '<C组目录>/report.json' --output '<新文件>/comparison.json'
```

比较器要求标准集、书、模型、问题、快照和调用预算一致，重新汇总逐题评分，保留错误题分母并报告 C-B 差值。它拒绝覆盖原报告或已有输出文件；不会把 JSON 格式错误归因为检索失败，也不会把相同调用上限当成相同上下文 Token 预算。

当前执行范围与评分规则：

- 在全新隔离数据目录中，通过生产仓库写入冻结 Source 与词法索引，再调用正式图治理编排器和查询编排器。该路径没有经过产品中的风格、梗概、草稿与发布界面门禁。
- 按章节截止点顺序建图，不预先加载未来章节。每道题重新隔离历史模型消息，记录真实请求、结果、读取证据、耗时及供应商返回用量。
- 答案只做首尾及连续空白规范化；同义答案必须明确列入参考答案。仅对模型实际读取且可映射回冻结原文的 Source 内容计证据分，不从图引用反推“已读原文”。
- 回答正确、至少一组必要证据完整、上下文隔离通过，三者同时满足才算联合通过；未知题要求明确拒答。出错和无效题保留在分母内。
- 建图失败会使依赖该快照的已选题记为错误。这些题并未实际调用查询模型，不能报告成查询已运行。
- 输出位于 `.worldseed-data/acceptance/knowledge-graph/<run>/`，包含 `report.json`、`build-*.json`、`query-*.json` 和隔离数据库。报告有标准集摘要、Git HEAD 和已跟踪差异摘要；目前没有逐文件记录未跟踪代码和构建产物摘要，复现时须保留当时工作目录。
- 用量仅包含适配器返回的供应商统计；执行失败且没有返回用量的调用以 `executionsWithoutReportedUsage` 单列，因此合计不是完整账单。耗时包括真实执行与重试。

当前每个短章只有一个 Source 单元，证据检查可定位到必要句，但检索粒度仍较粗。短章检索结果不能推导出长篇召回表现。已运行首批 6 题的 B/C 对照，详见 [首轮实测](knowledge-graph-evaluation-results.md)；相同调用次数及检索轮次上限不等于相同实际上下文 Token 预算，本轮不声称已控制 Token 预算。声明级 Precision/Recall/F1、faithfulness、引用支持率、D 组标准证据诊断、世界线/pending 攻击及重启恢复尚未实现或执行。
