## 暴露的问题

### 未知未来被当成当前状态

问题：“截至第二章，水市开张那天铜鱼令会由谁保管？”第二章只记录目前转交给许槐，水市开张尚未发生，当天是否再次转交未知，正确行为是拒答。图谱组与 Source 组都回答许槐。

C 组 `query-5.json` 中，模型在 interpret 阶段已经明确承认“水市开张本身尚未发生，开张当日保管人无独立记载”，随后仍用第二章末持有人作答；source_retrieval 保留了缺少未来证据的说明，但 response_review 仍判定 evidenceClosed。不是偷读第八章，也不是查询执行失败，而是时间条件被替换、回答审核未拦住无依据推断。该质量缺陷尚未修复，不通过改金标或删除失败题消除。

### 图治理临时 ID 契约不一致，已修复

首次尝试在第一章图候选生成后失败：紧凑路线的 dependency_audit 引用了已声明的 `local:time_preflood` 等临时身份，而该阶段只接受已落库 ID。已将允许集对齐其他候选处理阶段：已读图身份加本轮已声明临时身份；未声明身份和未读证据仍拒绝。回归测试先复现失败，再验证修复。复测 3 章分别提交 20、17、17 个图 mutation，证明本次阻塞已解除。

第二章 graph_spacetime_settlement 还出现过一次未声明临时 ID，供应商适配器通过正常修复重试后成功，轨迹仍保留警告；没有关闭引用校验。

## 隔离与局限

两组各 36 次查询适配器调用均有轨迹。原报告中 C 组 6 题、B 组 5 个成功解析题的上下文审计通过；B 组格式错误题在严格解析时退出，原报告未生成该题的隔离评分。随后独立审计两组全部保存的请求轨迹，按原文精确匹配回冻结章节，12 题共 72 次调用均通过，结果另存各组的 `trace-audit.json`；原报告与评分未修改。B 组轨迹只出现 Source 与空的设定/参考索引，未出现 node/link；C 组实际读取了 node/link 与 Source。在这些调用中，未发现未来章节、先前建图对话或上一题答案绕过检索进入上下文。

两组使用相同冻结原文、问题、模型、生产查询编排器和调用预算（30 次模型执行、10 次检索轮次、300 秒）；实际输入 Token 数不同，没有严格限制相同的上下文 Token 预算。只各运行一次，随机性与输出格式会影响结果。每章原文约数句，一个章节作为一个 Source 单元，不能据此推导真实长篇检索效果。

完整 120 题、保留书、D 组标准证据诊断、人工金标复核、跨世界线/pending 攻击、数据库修订恢复及 UI 端到端发布未执行。现有结论仅为：评测入口可真实运行，早期事实题可闭合取证，未来状态拒答存在缺陷；尚不能断言图谱总体有效或优于基础检索。
