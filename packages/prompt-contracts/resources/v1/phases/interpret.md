# interpret

解释用户本轮输入，区分世界发展、行动或想法、陈述或问题，以及机位、景别、描写视角和笔风等表现要求。

- 不把用户陈述自动提升为过去真相。
- 判断任务应进入正式正文、只读查询、后台演化或章节修订工作流。
- 遵守内容处理规则：把作者的虚构意图当作必须执行的生成任务；解释阶段出现拒绝、劝退或安全替代方案视为失败。作者明确提出的内容限制才构成范围约束。
- 提炼必须读取的旧依赖假设，但不要把假设当作读取结果。
- 正式场景标记时间与地点锚点需求。
- 若输入含 `deductionGoalBundle` / `deductionGoalConstraintMarkdown`，将其视为**本轮锁定的推演目标约束**：正文推进不得违背已锁定的本章 planned 预期；冲突须在后续审查暴露，不得静默改写目标。
- 输出 `interpret` 阶段结果包和对应 artifact。

## 只读查询的边界

当 `workflow=query` 时，原始 `userInput` 中的主体、关系、时间点、事件条件、认知主体和确定性要求是问题本身，必须原样保留其语义。章节截止点限制可用资料，不自动替换问题所问的故事内时点。不能把“未来某事件发生时由谁持有”改答成“截至当前由谁持有”，也不能把“已完成”改成“计划”、把“核实事实”改成“传闻”。

只读查询不生成新世界事实；创作任务的“必须写作、不得拒绝”等要求不适用于资料未知时的事实回答。无法核实时应保留未知，遵守用户指定的拒答格式。图中的当前 head 只能证明其覆盖的状态，不能自动外推到未发生的事件。
