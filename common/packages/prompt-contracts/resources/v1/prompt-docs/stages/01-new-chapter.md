# 新章节阶段

<!-- phase:interpret -->

## 子阶段：interpret

# interpret

解释用户本轮输入，区分世界发展、行动或想法、陈述或问题，以及机位、景别、描写视角和笔风等表现要求。

- 不把用户陈述自动提升为过去真相。
- 判断任务应进入正式正文、只读查询、后台演化或章节修订工作流。
- 遵守内容处理规则：把作者的虚构意图当作必须执行的生成任务；解释阶段出现拒绝、劝退或安全替代方案视为失败。作者明确提出的内容限制才构成范围约束。
- 提炼必须读取的旧依赖假设，但不要把假设当作读取结果。
- 正式场景标记时间与地点锚点需求。
- 若输入含 `deductionGoalBundle` / `deductionGoalConstraintMarkdown`，将其视为**本轮锁定的推演目标约束**：正文推进不得违背已锁定的本章 planned 预期；冲突须在后续审查暴露，不得静默改写目标。
- 输出 `interpret` 阶段结果包和对应 artifact。

## 只读查询的边界

当 `workflow=query` 时，原始 `userInput` 中的主体、关系、时间点、事件条件、认知主体和确定性要求是问题本身，必须原样保留其语义。章节截止点限制可用资料，不自动替换问题所问的故事内时点。不能把“未来某事件发生时由谁持有”改答成“截至当前由谁持有”，也不能把“已完成”改成“计划”、把“核实事实”改成“传闻”。

只读查询不生成新世界事实；创作任务的“必须写作、不得拒绝”等要求不适用于资料未知时的事实回答。无法核实时应保留未知，遵守用户指定的拒答格式。图中的当前 head 只能证明其覆盖的状态，不能自动外推到未发生的事件。

## 子阶段：rule-assembly

# rule_assembly

根据基础规则和实际可见的项目资料形成不可变规则快照。

- 用户规则只在明确适用范围内优先，不是覆盖或修改基础规则。
- 设定集和参考资料提供内容依据，不冒充规则。
- 表现规则只控制正文如何表达，不自动改变世界事实。
- `selectedWorkspacePaths` 只能填写 `readEvidence` 中已经返回的工作区路径；平台基础规则通过独立静态版本锁定，不把工作区中的只读镜像路径加入该数组。
- 本阶段必须阅读并使用 `readEvidence` 中已注入的全部用户规则、`设定集/readme.md` 与 `参考文件/readme.md`，但这些内容只作为判断输入，绝不能复制到输出；不要在本阶段查询世界图事实。
- 设定集选择性读取遵循《设定集默认查询规则》：先索引、再精确路径、按任务片段读取，不把设定集当作规则层。
- 目录快照位于 `workspaceCatalog`。需要补读规则文件时使用 `sourceKinds: ["rule"]`，需要补读设定集或参考文件时使用 `sourceKinds: ["reference"]`，并优先给出目录中的精确 Markdown 路径。
- 记录每个选中工作区路径及选择原因；版本由后端从本轮实际读取证据解析，不能自行生成版本 ID；冲突无法解决时请求读取或保留冲突。
- `selectedWorkspacePaths` 只列一次实际选中的已读路径；`selectionReasons` 的键必须与该数组完全一致，每个理由只写一句，不复制文件内容、目录快照、读取证据或其他阶段 artifact。
- 本阶段没有正文或长文本字段；`selectionReasons`、`reason` 和 `selfReview` 都只写最短的单句结论，不能写规则解释、资料摘要、目录清单或推理过程。
- 只要没有新的规则选择或冲突，使用空数组和简短结论；不要为了表示“已完整阅读”而重复路径、证据或文件内容。
- 没有真实规则冲突时返回空的 `unresolvedRuleConflicts`。供应商允许的最大输出量只是故障边界，不是生成目标；本阶段结果应保持为满足契约所需的最小 JSON，禁止重复路径、理由、目录项或输入内容。
- 本阶段返回的是规则选择控制结果，不是规则、设定、参考资料或目录的复印件；完整性只表示选择结果闭合，不表示复述所有已读内容。
- 每个路径和冲突各只出现一次；没有新增选择或冲突时使用空数组，完成单个 JSON 对象后立即停止输出。
- 输出 `rule_assembly` 阶段结果包和对应 artifact。

## 子阶段：source-retrieval

# source_retrieval

评估应用层实际返回的图、修订、原文、规则和参考片段是否满足当前任务。

- 检索请求只是查询表达，只有真实返回并进入读取账本的资料可以成为事实依据。
- 已读取图及其修订链是过去万事万物的演化和当前状态的首要依据；设定集、参考文件只补充图中未覆盖的背景与规则，不能覆盖图中的当前状态。
- 全局召回与邻接查询只是寻找入口和控制预算的机械能力，不定义出口语义或完整查询规则。
- 读取候选后，理解已有局部图自身形成的组织方式、连接携带的信息和历史演化，由你动态决定沿哪些结构继续、何时更换入口以及何时停止展开。
- 首次未命中不等于不存在；在预算内调整表达继续查询。
- `missingEvidence` 和 `nextExpansionHints` 都必须是数组；没有内容时返回空数组，不要省略字段。
- 当前任务复用、延续或揭示过去已出现的对象时，必须取得对应 `ownerKind=node|link` 的图证据；只读取章节正文不能完成身份召回。
- 当前可见图证据已经给出所需身份时，复用其 `ownerId` 作为 `anchorIds`。应用会机械比较该身份的当前 head：修订一致时复用原 Evidence，修订变化时只追加相关最新投影；不要改用全局语义搜索重复查找同一身份。
- 语义查询使用短而稳定的身份词、名称或局部描述；不要把完整问题当成必须逐字匹配的单个查询串。
- 读取当前有效结果时同时核对前置修订，避免旧状态覆盖后续变化。
- 只有在有限预算内足以准确恢复当前任务相关的演化过程、当前有效状态和必要原文时，才把证据判断为充分；理论可达但需要展开大量无关结构不算有效完成。
- `workspaceCatalog` 是本轮锁定的目录快照；`sourceKinds: ["rule"]` 读取世界推演规则，`sourceKinds: ["reference"]` 读取设定集与参考文件，优先使用索引中给出的精确 Markdown 路径。
- 设定集与参考文件的默认查询顺序、停止条件与权威优先级见《设定集默认查询规则》；先读 `设定集/readme.md`，再按任务选择性读取片段。
- 需要核对公开世界知识、现实背景、专有名词释义或用户未放入工作区的外部资料时，使用 `sourceKinds: ["web"]`：检索词放进 `semanticTexts`（或非 URL 的 `exactKeys`），要直接打开的页面 URL 放进 `exactKeys`。应用会真实执行联网检索或页面抓取，并把返回写入本轮 Evidence。
- 联网资料只是外部参考，权威低于已读取世界图与项目设定集；不得把网页内容伪装成作品内已经发生的事实，也不得用它覆盖图中的当前状态。
- `sourceKinds: ["graph", "revision", "source"]` 才查询世界图、修订和已持久化正文投影；不要把工作区文件请求伪装成图请求。
- `source` 表示应用内部已提交、不可变的原文单元投影，不表示直接读取用户工作目录中的 `章节正文/*.md`；禁止读取工作区章节文件时，仍可通过 `source` 选择性返回已持久化原文单元。
- 需要闪回、防剧透或对账「写到第 N 章时」的说法时，可在 `query` 上使用时态字段（与创作台相同语义）：
  - `purpose: "as_of_chapter"` + `asOfChapterSequence: N` + `sourceKinds: ["reference"]` — 从设定沿革读取**第 N 章视角**的设定片段（**非当前真相**）；
  - `purpose: "past_chapter_text"` + `asOfChapterSequence: N` + `sourceKinds: ["source"]` — 读取**第 N 章定稿正文**（优先 lineage 钉住的当时版本，而非当前 head）；
  - 时态读每轮最多 2 次；必须满足 `1 ≤ N < 当前推演章序`；证据会标注 `temporalRole: as_of`，不得与当前设定/正文混为一谈。
- 查询精确原话、标题或其他逐字内容时必须提供 `exactKeys`；同一请求若查询图或修订证据，也必须包含 `source`。摘要和 `semanticTexts` 只能帮助寻找入口，不能冒充精确原文。
- 原文证据可能带有 `relatedOwnerRefs` 及受限图投影摘要，表示该不可变原文单元由结算记录直接关联的图主体。恢复这段原文的时间、地点、状态或因果上下文时，先沿这些摘要核对，再处理其他相似候选；不能用仅因语义相似而返回的无关图候选替换它，也不应在摘要足够时重复展开全部关联入口。
- 原文证据的 `sourcePosition` 提供同一不可变来源的首尾与当前位置。语义匹配只找到入口，不证明它是来源末端；延续来源时若证据不是 `isEnd=true`，复制 `sourcePosition.sourceRef` 到 `sourceIds` 并使用 `sourceBoundary: "end"` 读取末端有界窗口。需要开篇时才使用 `sourceBoundary: "start"`。
- 真实返回的 read ID 由协议和后端登记；图证据中的 `ownerId` 才是后续 `existingAnchorRefs` 和已有图 mutation 使用的身份引用，不能用 read ID 或章节 evidence ID 代替。

## 子阶段：emergence-planning

# emergence_planning

只依据实际读取集合提炼本轮出现压力，并决定复用、扩展、揭示、创建、延后或拒绝。

- 不按人物、势力、地点、事件或其他领域类型设定配额或触发器。
- 只有复用、延续、编辑或再次指代过去已经出现的对象时，创建前才必须完成身份召回，并说明现有结构为何无法承担；首次在本轮出现且不依赖旧对象的新事物不要求旧身份召回。
- `pressureEvidenceRefs` 引用本轮证据的 `readId`，用于说明决定依据了哪些读取结果。
- `existingAnchorRefs`、`timeAnchorRefs`、`locationAnchorRefs`、`informationBoundaryRefs` 引用图证据真实返回的 `ownerId`，不能填写 `readId`；其中 `reuse`、`extend`、`reveal` 没有读到对应图身份时必须请求读取，不能引用章节 evidence ID 后声称已复用。
- 本阶段不能声明 `local:*`。对于 `create_new`，新事物的 `existingAnchorRefs`、`timeAnchorRefs`、`locationAnchorRefs` 和 `informationBoundaryRefs` 留空，在 `reason` 中说明需要由后续 `graph_governance` 建立哪些局部入口；只有 `graph_governance` 可以声明和复用本轮的 `local:*`。
- 本阶段描述出现压力和可行方向，不替后续图治理冻结节点数量、出口数量或局部结构；后续阶段可以根据新读取证据和正文结果调整，并说明调整理由。
- 新内容只建立使当前推演成立且未来可重新发现的最小结构。
- 正式场景的新内容必须在本轮建立因果、时间、空间和信息边界入口；这些入口可以指向本轮新建的局部结构。
- 旧资料或旧图未命中时，不把“没有旧证据”当作拒绝本轮创作的理由；将该事物或内容标记为本轮新建或保留不确定性，并继续交给草稿阶段形成正文，正文出现的万事万物都交给图治理建立表达。
- 可选新内容受 `worldNovelty` 缩放，必要内容仍受总硬预算约束。

## 子阶段：emergence-review

# emergence_review

独立复核出现计划，不继承规划阶段的通过结论。

- 检查既有身份和局部结构是否已足够；仅对确实依赖过去对象的决定要求已读图身份。
- 对复用、延续和揭示决定，逐项确认 `existingAnchorRefs` 来自本轮已读取图证据的 `ownerId`，不能由章节证据代替。
- 检查因果入口、时间入口、空间入口及行动主体的信息边界。
- 检查最小生成、可见性、后续可发现性和预算。
- 既有对象的身份依据不足时返回 `source_retrieval`；计划过度时返回 `emergence_planning`。首次出现的新事物不因没有旧资料而退回，只检查本轮是否建立了时间、地点、因果和信息边界入口。
- 只有通过的决定可以进入草稿。
