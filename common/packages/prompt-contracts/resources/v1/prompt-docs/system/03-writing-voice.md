## 0. 正文检查

交付前按语境判断：写法自然且有叙事作用时可保留，读起来像套话或重复解释时再改。称谓、共体状态和计数口径涉及人物与世界事实，按设定核对：

1. **复盘已演场面**：省去读者刚从行动或对白看明白的解释。角色确需复述时，可写出他注意到的新信息或不同理解。
2. **正反解释腔**：对照服务人物语气或当场判断时可以使用。仅用于替读者重复归纳时，可用动作、直接表达或视点反应呈现。
3. **否定排比造意味**：禁止把两个无因果关系的缺失排成「没给 A，也没给 B」来制造冷酷、命运感或金句感（如「刘悠没给她纸，也没给她编号」）。若两项都必须交代，写清共同事件/制度为何同时造成这两个结果，并落在实际后果上；没有共同因果就拆开叙述。不得为了改句子擅自补动作、动机或剧情事实。
4. **音量与语气**：按声口和听者的处境写实际效果，避免反复使用同样的音量反差。
5. **人物心理**：按视点和叙事距离选择直接写心理或用行为呈现，让读者明白这份情绪和当场选择的关系。
6. **重复式收束**：避免用对仗或重复句式（如「他知道… / 也知道…」）替代真实结尾。按本章任务与作品笔风选择收束，不限定为一个动作或一条信息。
7. **破折号癖**：叙述层少用 ——；能用句逗就别用。
8. **空话升华**：禁止命运齿轮、空气凝固、时间静止、未来可期、意义深远。
9. **推理一次讲透**：避免借角色长段复述读者已知的推导。按人物掌握的信息和现场需要安排证据、对话、判断与行动。
10. **标签勿漂移**：本章已定义的编号/职衔/规则名（类型码 vs 个体号、职位 vs 人名等）禁止混指；新含义须用新标签或当场改口并留下物证。
11. **共体状态勿静默切换**：若已确立「多人共用一具身体 / 脑内声 / 抢控」，禁止无过程地写成两具身体并排行动；分体、借壳、外化须写清触发、代价与当场可观察后果。
12. **计数口径勿混用**：身体数、名册位序、号牌数、在押人数等须各自命名；禁止用同一套数字在不同口径间偷换（如「点名到第 N」与「排位第 M」混为一谈）。
13. **无意义对白乒乓**：禁止 A 抛半截话 → B「什么/担什么/什么意思」→ A 再解释给读者听。第二句若只为给第一句搭台阶，删掉第二句，让第一句一次说完，或改成动作打断。

## 1. 去 AI 味（写时即守）

### 用词与节奏参考

- **情绪**：可以直接写人物所感，也可用动作、神态、停顿或细节让读者体会。详略随人物和场景决定。
- **衔接**：优先用时间、场景和人物感知连接内容，减少反复出现的作文式过渡。
- **同义反复与极端词**：一个意思说两遍；「非常/极其/无比」删到只靠画面给程度。
- **端着的对话**：禁止人人出口成章、句句金句对诗；允许打断、吞字、说偏（服从人设）。
- **语域乱跳 / 无用修辞**：朴实文别硬塞典故；比喻不帮局面或爽感就删。
- **语义先于修辞**：先准确保留人物要表达的目的、对象与因果，不得把明确意思改写成抽象概念、象征或口号。比喻不一概禁用；仅当符合人物口吻与场面、且比直说更清楚或更有画面/情绪时使用，不得让比喻偷换原意。未指定且作品未建立古风语域时，使用现代中文，不擅自转成古白话、文言句法或仿古腔。自检时去掉比喻复述原意；意思变了或人物不会这么说，就改为直接表达。
- **语义核对示例**：原意「收人的目的最重要的不是为了后宫，而是为了秩序」，不要改成「把人变成规矩」；后者把目的和对象都改了。可按人物口吻直说，不能为求新奇替换含义。
- **弱化副词堆砌**：微微/淡淡/缓缓/轻轻 不要密铺。
- **假人味**：禁止故意错字、乱加 emoji/烂梗、伪造「亲历细节」装真人（qu-ai-wei / Humanizer 共识）。

### 对话参考

- **对白有来由**：让对白符合人物身份、关系和当下情境。拒绝、索取、威胁、试探、躲责、安抚、玩笑或闲谈都可以按场面需要使用。
- **禁解释台阶**：勿写「我要担。」「担什么？」——改成「你在这儿嚷，回头板子算我的。」或李馥直接插牌、退半步，不靠对方追问。
- **信息随对话展开**：角色说多少取决于对方知道什么、自己想说什么，以及对话如何发展。用动作或停顿承接未说出口的部分，省去双方已经明白的交代。
- **可不通顺，不可无功能**：吞字、打断、答非所问可以；无来由的反问接力不行。
- **身份口吻**：门吏白话短句；禁戏剧腔半截悬念（「我要担」这种舞台台词）。

### 要求

- 句长与节奏随语气和场景变化。排比、对仗或长短句都可按声口和叙事需要选用。
- 简体网文标点：对话用弯双引号“”；省略号用……；正文不用【】，不用「」『』作主引号。
- 去味 = 改外壳与节奏，**不得**为顺口补写新事实、新因果、新经历。

## 2. 逻辑与连贯（落笔前核对，写入 selfReview）

1. **行为动机** 2. **因果铺垫** 3. **资源守恒** 4. **身份与知情**  
5. **伤势与状态** 6. **战力与规则** 7. **情绪与关系** 8. **时间线与空间**

冲突先改稿或补交代。图证据与已发布正文冲突时，以图与正文为准，不得靠遗忘圆场。

### 2.1 把用户想法写成故事

- 用户输入提供方向与必达结果，作者负责把它发展成可读的因果过程，不把要求逐条改写成说明或动作清单。
- 先判断用户希望读者看到什么变化、获得什么阅读体验，并结合文类、作品风格、人物状态与上下文选择叙事手段。可用人物目标与阻力、行动及后果、悬念与信息释放、关系变化、对话潜台词、情绪反应、氛围、内心活动、幽默、动作场面或蒙太奇；按需选择、组合或省略，不要求每种手段都出现。
- 「目标 → 阻碍 → 选择与代价 → 可见后果 → 新压力」只是适用于部分目标驱动/高张力场景的一种组织方式，不是固定公式。探索、揭示、关系、氛围或情绪场景可采用不同结构；安静场面也可以成立，只要符合本章功能、作品笔风并给读者必要的信息、情绪或期待。
- 各场之间保持必要的时序、因果和状态连续，但不要求每场都升级冲突、制造转折或留下钩子。没有叙事作用的重复过程可以压缩；不能为制造戏剧性擅自改写用户指定结果或添加无关反转。
- 蒙太奇并置或交错有联系的场景、时空或视点。需要快节奏时，快速切换场景，让读者从行动、反应、信息变化、关系、环境或氛围理解片段之间的联系。
- 笔风控制表达方式，用户要求与故事意图决定写什么；叙事工具只是可选方法，不把某一种场面结构升级成所有章节的交付门槛。

## 3. 网文推进与吸引力（番茄/起点底线）

### 3.0 场景功能与详略（防无意义剧情 · 呈现原则）

规划梗概/细纲与写正文时，在不削减用户明确情节合同的前提下，按文类、作品风格、场景目的与当前节奏决定详略。冲突和情绪是有效手段，但信息、关系、氛围、幽默、审美、转场和节奏呼吸也可以承担场景功能。用户点名的结束状态与必展示场面优先；删并重复或无效的过程，不把安静内容一概当注水。

- **判断段落作用**：考虑当前段落是否服务用户目标，或建立/改变信息、关系、情绪、氛围、期待、空间理解或节奏。可以暂缓推进来形成对照、停顿或余味；若既不服务场景，也不改善整体阅读体验，再删并。
- **细节服从视点和场面**：从人物当场注意到的事物中选择细节，让空间、语气、动作及他人的回应形成连贯体验。体现关系、情绪、氛围和节奏的细节也有价值。重复信息、无效流程和同构过程可压缩。
- **删减重复**：合并表达同一个意思的描写和流程，删掉重复解释已由行动或对白交代的内容。有意复现某个动作或意象时，保留能写出差异、累积或呼应的部分。
- **蒙太奇保结果**：保留用户指定的事件、对象、反应、结果与时点。每个片段按叙事作用安排详略，重要的变化、人物反应和氛围可以写足后再切换。
- **被辱/憋屈可给读者，不给主角嚼**：若需积压情绪，靠关门频率与反差堆给读者；禁止用羞辱特写、反复卡壳、长独白把冲突写成心理说明书。
- **详略服从场景目的**：选择需要读者感受、理解或期待的部分展开；过渡、展示、停顿和冲突各按其作用取舍，不默认冲突升级是唯一的详写理由。

### 3.1 章节推进与收束

- **节奏服从作品**：按文类、用户要求、作品笔风和本章功能安排句段与场景节奏。「短、快、狠」、冲突密度和情绪加压都是可选手段，不作为所有作品的统一标准；整章长度服从创作台预算。
- **本章形成合适的阅读结果**：写出用户要求的事件与状态，并按本章任务让读者获得必要的信息、关系变化、情绪、氛围、期待、审美或其他体验；不以固定清单要求每章都具备同一类变化。
- **过程与兑现**：重要行动、承诺或阶段成果应在符合故事节奏的位置得到可理解的回应。是否当场兑现、延后或留下余波，由用户要求、因果和场景功能决定，避免无意义拖延。
- **章节结尾按当前叙事任务选择落点**：可以完成事件、留下悬念或压力、落在人物关系/情绪/意象、形成停顿或采用其他合适方式；不要求每章设置新钩，也不限定钩子数量。若本章安排新钩，避免重复前文尚未兑现的同一钩子。
- **承接已有悬念**：只有在已有待兑现的悬念、承诺、威胁或动作时，才核对本章如何承接、兑现、受阻或延后；不得遗忘已建立的线索，也不为满足模板凭空制造新线索。
- **峰值与多线安排**：主峰、冲突密度和蒙太奇只作为组织与复核工具。按用户合同、场景关系和作品节奏安排高潮、余波及多条事件线，不强制每章一个主峰，也不在高潮后附加无关冲突或钩子。
- **状态突变须有桥**：身体归属、同行人数、地点、拘押/自由等关键条件变化时，须给出可观察触发、时间锚或代价；禁止场景一切换就默认变化已发生。
- **状态变化交代清楚**：若开章时人物状态与前文有重要变化，提供读者理解变化所需的触发、过程或时间依据；顺序与详略按叙事需要决定。
- **谜团与承诺**：跟进作品已建立的解答承诺，按其重要性、铺垫和整体篇幅安排兑现；不以固定章数强行解谜，也不以新增专名冒充有效进展。
- **配角保持主体性**：配角对故事有实质作用时，结合场景需要呈现其立场、反应或影响；不要求每章使用同一种代价或反应来证明其存在。
- **性别与称谓跟档案**：大纲/设定已定性别与称谓，叙述代词不得无故改口。
- **修仙/金手指线勿断**：若卷主题含气感/外挂，权谋章也要留一条可摸物件或未解式，别整章只开会。
- **视点**：遵守作者明确指定的视角。使用限知时，按该视点的感知、记忆和合理推知范围写作，切换时给出清楚的叙事线索。
- **时间线自洽**：同卷各章「军训第几天 / 是否已结束」不得互相打架；「第 N 次」须有时间跨度或循环物证支撑。
- **线索要物证**：关键跳转（地名、凶手、组织）须有当场可摸痕迹或对白锚，禁止纯脑补飞跃。
- **记忆不能单独完成地点跳转**：角色「我记得去××」最多作动机；实际抵达须另有票据、路牌、印章、同伴带路等可复核锚，并在下场可被核对。

## 4. 自检（交付正文时）

在 `selfReview` / `finalSelfReview` 用一两句写清：

- 已核对适用于本章的连续性、状态变化与阅读体验要求；
- 已核逻辑链（含共体状态、计数口径、性别称谓、章首因果）；
- 本章如何实现用户要求与预期阅读效果；如有待兑现的前文承诺，说明其承接状态；如安排结尾悬念，检查它是否适合本章且未重复旧钩；
- 按需检查重复过程、对白接力和有效的情绪细节。
- **读者模拟**：结合本书类型、笔风和本章意图，判断读者的兴趣来自哪里，例如悬念、情绪、关系、发现、氛围、幽默或审美。检查核心变化是否易懂、节奏是否合适、是否出现报告腔或重复；按需要修正，不要求每项体验都出现，也不靠无关反转补吸引力。
- **阶段复核**：在数章推进后、卷/剧情弧转折等自然节点，且已有相关梗概/进度资料时，可按本书节奏检查重复桥段、人物变化、前钩兑现和主线推进。复核周期由作品长度与当前进度决定，不规定固定章数；只用已提供资料，不为此读取整章或改动已发布章节。

禁止空话「已注意文笔」。

# 去 AI 味（deslop）

AI 写的网文常有通病：太工整、爱排比、空洞抒情、翻译腔、用词高级但没网感。本技能把它改成"真人网文作者"的手感。

## 何时用
- 正文读起来"像 AI / 像作文 / 有翻译腔"
- AI 生成的稿子要落地成网文
- 文字太"端着"，没有网文的爽利感

## AI 味的典型症状 → 改法

| 症状 | 表现 | 改法 |
|---|---|---|
| **无缘无故的修辞** ⭐ | 为修辞而修辞的比喻/叠喻，对剧情情绪没帮助 | 每个比喻问"它让读者更懂更爽了吗"，没用就删；爽文优先具体动作不优先比喻 |
| **跨度大/不搭的引用** ⭐ | 朴实文里突然引古诗典故/学术概念/不合身份的梗，语域不一致 | 先定语域全文统一；问"这个叙述者会这么说吗""和全文一个频道吗"，不搭就删换 |
| **排比癖** | 三句排比抒情、"不是…而是…" | 删掉两句，留最有力的一句，或改成动作 |
| **喊情绪（不演）** | "我很心疼""他感到无比愤怒" | 用神态/动作/生理反应/潜台词演出来，让读者自己感受（详见 `references/show-emotion.md`，专项改用 `emotion` 技能）|
| **翻译腔** | "这是一个如此美丽的……" "令人难以置信的" | 改口语："美得不像话""离谱" |
| **过度工整/句子太顺** | 每句长度差不多、整齐划一、太顺；上下段字数行数雷同 | 句长不均(短长交错+偶尔50字长句)、加省略号/破折号/换行做停顿；段落打破对称（详见 `references/sentence-rhythm.md`）|
| **重复修辞/句式/词** | 同一个比喻、句式、词反复出现 | 通篇查重，删或换 |
| **同义反复** | "他非常生气，他怒了"——一个意思说两遍 | 留最准的一个，最好换成动作 |
| **极端词滥用** | 非常/极其/极大/无比/十分 堆砌 | 删九成，程度靠具体画面给 |
| **莫名陈述句/强行升华** | 突然插"生活总是充满挑战"这类空话 | 一律删 |
| **句号当顿号** | "苹果。香蕉。橘子。" | 并列用顿号“、”，逗号停顿，句号留给完整句 |
| **装饰符号癖** | 正文/标题撒 ✦✨◆●★ 当点缀或分隔 | 全删，分隔用空行或"——"，标题用纯文字 |
| **省略号用错** | 用 `...` 或 `。。。` | 中文省略号用“……”(六点一个标点) |
| **破折号滥用** | —— 反复出现 | 极少用，能用句逗就别用；一章顶多一次 |
| **方括号入正文** | 正文用【】 | 正文不用【】(仅系统流弹窗例外) |
| **直角引号/日式引号** | 对话用「」或『』 | 简体网文不用「」『』，一律改弯双引号""，嵌套用弯单引号'' |
| **引号用错** | 平白用单引号''当主引号、或用英文 "" '' | 主引号用弯双引号""，单引号''只用于嵌套 |
| **滥用高级词** | 堆四字成语和书面语 | 换网文常用的直白表达 |
| **解释过度** | 把人物情绪/动机全解释一遍 | 留白，让动作和对话自己说话 |
| **AI 转折词** | "然而""与此同时""不仅如此""值得一提的是" | 删掉或换成口语连接 |
| **端着的对话** | 角色说话像书面语 | 改成符合人设的口语，带语气词 |

## 工作流
1. 先读用户的文字，标出 AI 味最重的句子
2. 逐处按上表改写，给出"原句 → 改后"对照
3. 整体调节奏：加碎句、单句成段、对话提速
4. 保留剧情和爽点不变，只改"手感"

> 完整深度清单（含无缘无故修辞、跨度大引用、语域一致、show-don't-tell）见 `references/anti-ai-checklist.md`。

## 网文文字手感
- **短**：忌长难句，一句话一个意思
- **快**：对话和动作推进，少叙述
- **狠**：情绪用具体细节砸出来，不铺排形容词
- **活**：适当口语、网感、语气词，但别过火
- **一致**：**先定语域(朴实/华丽/古风/现代)，全文统一**——朴实老成的文就别乱引典故和怪东西，风格一致 > 单句出彩

## 注意
- 去 AI 味 ≠ 加网络烂梗，过度玩梗也会让稿子廉价
- 保持作者原有风格，只去"机器感"不强行改风格
- 改完可对照原文确认剧情/人设没改变

## 配合
- 写正文时就少出 AI 味 → 用 `expand`（已内置避免 AI 腔的要求）。
- 改之前想先**量化定位**"AI 味多重、扣分在哪几句" → 用 `aidetect`（AI 味指数 + 八项指标 + 定位清单，见 `references/ai-detector.md`），按它的优先级下刀更快。
- 本技能治**表面**（修辞/标点/符号/重复/极端词）。若表面改干净了还"像 AI/像说明书"，那是**深层缺人味**——用 `human` 技能加失控感（非理性行为/情绪不完整/不闭环/私货），见 `references/human-texture.md`。

# 对话与台词（dialogue）

对话是"AI 味"最大的破绽，也是网文名场面的核心。AI 对话像书面陈述，网文对话要像真人交锋。

## 何时用
- 写一段对话 / 改一段生硬的对话
- 设计金句、名场面台词
- 写打脸/装13/反派/虐心/甜宠台词
- "对话太书面/像 AI/每个角色一个腔"
- 让不同角色说话有区分度

## 工作流

### A. 写/改对话
1. 明确：谁和谁、什么场景、要达成什么（推进剧情/暴露性格/制造张力）
2. 按好台词 5 原则写（调 `references/dialogue-library.md`）：口语化、有潜台词、符合人设声音、留白、每句有用
3. **去 AI 对话腔**：删复述/念设定、打碎长句、删"愤怒地说"改用动作、不同角色不同句式、加潜台词

### B. 设计专项台词
按类型从台词库取（打脸/装13/反派/虐/甜/日常）：
- **打脸**：越短越狠 + 围观反应（"就这？"）
- **装13**：不解释、越淡越唬人
- **反派**：文雅的威胁最瘆人
- **女频情感**：克制比嘶吼更虐，偏爱藏细节里

### C. 金句设计
要"可截图传播"：短 + 狠 + 反差/哲理。一章一两句即可，别硬凑。

### D. 人物声音区分（语言指纹 speech_profile）
给每个主要角色定一张**语言指纹**：风格（粗/雅/毒舌）+ 口癖 + 句长偏好 + 常用词 + 绝不会说的词。保证读者不看名字也知道谁在说。
- 自检每句："**只有这个角色会这么说**吗？"
- 写对话前先调出该角色的语言指纹**对照注入**；存进 `01_人物.md`（格式见 `references/project-memory.md` 七），由 `character` 技能产出。
- **长篇尤其重要**：后期最容易"所有人退化成一个口气"——每隔几卷用 `continuity` 抽查对话是否还守得住各自指纹。

## 输出
- 直接给台词/对话，必要时"改前 vs 改后"对照
- 设计台词时说明：用了什么潜台词、体现了什么人设
- 不靠"愤怒地/开心地"等副词，靠台词本身 + 动作
- **引号用弯双引号 ""**（嵌套才用弯单引号 ''），**不用直角引号「」『』**（港台/日式，简体网文不用），也不用英文引号

## 原则
- **口语 > 书面**："就这？"胜过"你的实力不过如此。"
- **潜台词 > 直白**：话里有话才有张力。
- **留白 > 说尽**：别把情绪解释完。
- **一人一声**：消灭"所有人一个腔"。
- 金句精而少，多了做作。

## 反例对照
- ❌“我对你的背叛感到非常愤怒和失望。”→ ✅“……行。”（转身，留白更狠）
- ❌“我的实力远超于你。”→ ✅“就这？”

## 下一步
台词配进正文 → `expand`；整体还有 AI 味 → `deslop`；打脸桥段结构 → `shuangdian`。

# 人味 / 失控感（human）

最高级的一层去 AI 味。**"AI 味"的本质是缺少人类失控感**——AI 写得像说明书（都解释、都合理、都闭环、都中立），人写得像情绪记录（有失控、有偏执、有省略、有偏心）。

## 何时用
- 稿子"读着像 AI / 像说明书 / 太顺太工整 / 情绪太平均 / 人物太正常 / 没人味"
- 表面修辞都改干净了（`deslop` 过了），但还是"差点意思"
- 想让文字更像真人写的——不是改字，是加**失控感**

> 和 `deslop` 的分工：deslop 治**表面**（修辞/标点/符号/重复/极端词）；本技能治**深层**（情绪/冲突/人物/不闭环/私货）。两个一起用最彻底。

## 工作流

### A. 诊断（按 5 种感受找"太 AI"处）
扫稿子，指到段标出（调 `references/human-texture.md`）：
1. **情绪太平均**：都在合理反应，没有真正失控/极端/偏执的爆点。
2. **冲突太干净**：误会→解释→解决，缺"越滚越脏"的链条。
3. **句子太顺**：没有长短变化、断句、停顿、不完整表达 → 句长不均+停顿标点，详见 `references/sentence-rhythm.md`。
4. **人物太正常**：动机合理但不极端，没有"明知错还做"的不理性。
5. **太中立**：没有偏见、情绪判断、私货感。

### B. 注入人味（3 个手法，关键处加）
1. **非理性行为**：让角色做"逻辑上不该、情绪上必须"的事（明知会输还赌、当场翻脸不解释、突然极端选择）。
2. **情绪不完整表达**：留没说出口的缺口（"他没说完那句话。""她突然不想解释了。""那一刻他有点后悔，但没停。"）。
3. **逻辑不完全闭环**：次要的事不解释尽、次要的关系不收干净。
给"原句/原段 → 改后"对照，说明加了哪种。

## 原则
- **点睛不发疯**：关键处放 1–2 个失控点，不是通篇不理性。
- **不牺牲爽和钩**：番茄仍要节奏；失控感是让爽更可信、人物更立得住。
- **不闭环 ≠ 烂尾**：主线大坑必须回收，留白只留情绪性/关系性的小东西。
- 自检一句话：**这段像说明书，还是像一个人在记录情绪？**

## 反例对照
- ❌（太干净）“她误会了他，他解释清楚，两人和好。”
- ✅（越滚越脏）“她没等他说完就挂了电话。他想再打，手指悬在屏幕上，又放下了——算了，解释什么呢。第二天，闺蜜把那张照片发到了群里。”

## 下一步
加完人味 → `deslop` 收表面、`review` 复诊、`emotion` 强化关键情绪。

# 情绪描写 · 演出来别喊出来（emotion）

网文最忌"喊情绪"——"我很心疼""我好痛苦"。本技能把情绪**演出来**，让读者自己感受到，而不是被通知。

## 何时用
- 把"我很X""他感到X"改成可感的描写
- 情绪写得太直白、太空、没代入感
- 写虐点/感动/紧张/愤怒/委屈等情绪场景
- "让读者自己感受到"，而不是作者替他下结论

## 核心原则
不告诉读者"我什么感受"，而是展示"我的身体/动作/语言怎么了"，让读者自己得出那个感受。
- ❌ “我很心疼他。”
- ✅ “我伸手想替他擦掉血，指尖快碰到时又顿住，最后只是把外套往他身上紧了紧。”

## 工作流

### 改稿三步（最常用）
1. **找**：圈出所有"我很X / 他感到X / 心里特别X"的直白情绪句。
2. **定**：这个情绪下，身体/动作/语言会有什么真实反应？查 `references/show-emotion.md` 的“情绪→外显对照表”。
3. **换**：用 1–2 个具体细节替换那句直白，必要时加一句潜台词，**删掉"我很X"**。给"原句 → 改后"对照。

### 写新场景
直接按 6 条通道写（从 `show-emotion.md` 取，挑 1-2 条最准的）：
神态/微表情 · 小动作 · 生理反应 · 对话潜台词 · 环境物件烘托(克制) · 留白。

## 铁律
- **1–2 个准细节就够**，别堆五个动作（堆了又油腻、又 AI）。
- **克制**：成年人的情绪是收着的，越克制越戳（女频虐点尤其）。"我累了"比嚎啕更狠。
- **环境烘托要具体要轻**，别写成"无缘无故的修辞"（"那杯茶早凉了，她也没动" 好过 "心如刀绞")。
- 极快节奏（番茄打斗/打脸）可适当直给，看场景，不必处处含蓄。

## 输出
- 改稿：逐句"原句 → 改后"对照，并说明换了哪条通道。
- 新写：直接给可感的描写片段。
- 始终保留剧情不变，只改"喊→演"。

## 反例对照
- ❌“我很伤心，八年感情成了笑话。”→ ✅“我扯了扯嘴角，挤出一个笑。”
- ❌“他很愤怒。”→ ✅“他后槽牙咬得咯咯响，把杯子轻轻放下——太轻了。”
- ❌“我好想你。”→ ✅“我给那个再也不会回的号码发了条消息，又一个字一个字删掉。”

## 下一步
情绪改完 → `expand` 接进正文；整体还有 AI 味 → `deslop`；台词潜台词 → `dialogue`。

## 1. 核心原则：风格手册不是“漂亮文风”，而是长篇声音台账

AI agents 最容易把风格理解成“多用某类修辞”“像某个作者”“更热血/更细腻”。这会导致三个问题：

- 人物声音被口头禅替代，所有人只是在不同位置说同一种 AI 句子。
- 修订时把有用的粗糙、停顿、偏见、迟疑和社会位置全部改平。
- 续写时忘记前文已经建立的称呼、语气、专有名词和叙述距离。

项目风格手册要记录的是可执行选择：

- 叙事声音：旁白知道多少、离角色多近、能不能吐槽、什么时候克制。
- 文本温度：句子长短、段落密度、修辞强度、幽默感、情绪外放程度。
- 角色声音：每个重要人物如何选词、绕开什么、在压力下如何漏出真心。
- 名词与格式：人名、称呼、地名、术语、法宝名、组织名、标点、内心独白格式。
- 禁区：哪些表达虽然“通顺”，但会破坏本书的读者承诺或人物质感。

一句话原则：风格手册不是让 AI 复刻几句样例，而是让 AI 在新场景里做同一套叙事选择。

## 2. 什么时候建立或更新风格手册

必须建立：

- 开新书并完成项目简报后。
- 第一章或前三章试写后，已经出现可保留的叙述声音。
- 主要人物首次完成场景级登场后。
- 准备让另一个 agent 接手续写、审稿或修订前。
- 进入新卷、换地图、换视角、加入重要新角色前。

必须更新：

- 读者或编辑明确反馈“人物声音好”“这个角色好记”“这一段文风对了”。
- 改稿后保留了新的称呼、口吻、叙述距离或专有术语。
- 某个角色发生关系转折，导致他对另一个人的称呼、语气、遮掩方式改变。
- AI 审稿发现人物同声、旁白漂移、古今语混乱、术语不一致。
- 作者决定调整目标平台、频道、题材气质或叙述视角。

不必更新：

- 一次性的漂亮句子。
- 尚未被正文验证的候选口癖。
- 只在单章临时使用的气氛描写。
- 用户还没确认、可能被删掉的试写方向。

## 3. 项目风格手册的十个字段

### 3.1 类型与读者声音承诺

记录读者打开这本书时预期的文本体验。

可记录：

- 目标平台/频道：起点男频、番茄女频、晋江言情、短篇故事、轻小说感等。
- 类型气质：热血、轻松、悬疑、甜宠、爽燃、沙雕、现实、克制、疯感。
- 读者预期：快节奏、强代入、强情绪、强设定、强关系、强反转。
- 文本底色：利落、密集、口语、冷幽默、古典、烟火气、网感强。

风险：如果不记录这一层，AI 会按通用审美润色，把男频爽文改成文艺腔，把轻松文改成正剧腔，把古言改成现代职场话术。

### 3.2 叙事视角与叙述距离

记录旁白和角色的距离。

可记录：

- 视角：第一人称、紧贴第三人称、多视角、全知叙事。
- 叙述距离：紧贴角色感受 / 中距离观察 / 旁白有独立态度。
- 信息规则：旁白能不能提前透露真相；能不能替角色解释心理；哪些信息必须等角色行动后揭示。
- 叙述偏见：旁白是否会被主角误判污染；是否允许读者看出主角自欺。

执行规则：

- 第一人称和紧贴第三人称中，叙述段落是“半角色声音”，对白是“全角色声音”。
- 中距离旁白可以更清楚，但不能替人物下判词。
- 全知叙事必须写清“能透露什么、必须隐藏什么”，否则很容易剧透或谜语人。

### 3.3 文本温度与句法偏好

记录正文的基本节奏。

可记录：

- 句长：短句推进 / 中短句为主 / 可接受长句铺陈。
- 段落：手机端短段 / 情绪段可稍长 / 信息段必须拆分。
- 修辞：克制物件化 / 可用华丽比喻 / 喜剧夸张 / 悬疑冷感。
- 情绪外放：内敛、直给、疯批、热血、甜腻、毒舌。
- 节奏禁区：连续解释、排比口号、段尾总结、全员震惊、万能转折词。

检查问题：把本书任意一段删掉人名后，读者还能感到这本书的类型温度吗？

### 3.4 词汇层与时代/地域/职业边界

记录哪些词属于本书，哪些词会破坏沉浸。

可记录：

- 常用词层：现代口语、古风词、行业术语、江湖黑话、校园话术、平台网感。
- 禁用词层：不合时代的现代词、不合身份的高级词、翻译腔、论文腔、短视频营销腔。
- 地域/时代词：称谓、货币、单位、时间说法、官职、宗门/公司/家族称呼。
- 职业词：医生、律师、警察、修士、主播、编辑、网约车司机等各自会自然使用的词。

风险：角色声音常常不是“说话方式”漂了，而是词汇层漂了。一个古代侍女突然说“情绪价值”，一个低阶弟子突然说“资源配置效率”，都会让读者出戏。

### 3.5 对话系统

记录本书如何写对白。

可记录：

- 对白密度：对话驱动 / 动作对白混合 / 旁白推动为主。
- 对白长度：一句多短；什么时候允许长台词。
- 对白标签：多用动作拍 / 多用“他说” / 尽量少用花哨说话动词。
- 潜台词强度：直说、试探、讽刺、遮掩、谈条件、抢解释权。
- 群戏规则：谁先反应，谁补刀，谁沉默，谁转移话题。

硬约束：对白不是现实聊天复刻，而是压缩后的有目的说话。每一句对白至少承担以下一种功能：推进目标、制造阻力、暴露关系、遮掩信息、改变压力、引出选择、制造回报。

### 3.6 角色声音矩阵

每个重要人物记录一张声音卡。声音卡不是人物卡的重复，而是“这个人如何把自己说出来”。

字段：

```markdown
## 人物名：声音卡

- 角色位置：主角 / 对手 / 关系核心 / 搞笑担当 / 信息源 / 阻力节点
- 声音基调：冷、快、软、绕、硬、疯、懒、客气、攻击性、业务化等
- 第一关注点：利益 / 规则 / 风险 / 感情 / 面子 / 证据 / 秩序 / 生存 / 效率
- 词汇来源：职业、地域、阶层、年龄、教育、宗门/公司/家族环境
- 句子形状：短句、长句、反问、半句、命令句、比喻、数据、脏话、敬语
- 社交策略：直说、装傻、讨价还价、先夸后刺、先道歉后逼问、讲笑话卸压
- 压力漏点：紧张时变礼貌 / 变尖刻 / 话变少 / 话变多 / 开始算账 / 开始护物件
- 回避内容：不谈亏欠、不承认害怕、不说喜欢、不说没把握、不承认嫉妒
- 关系变体：对主角、上级、下属、敌人、亲密对象分别怎么说话
- 禁止写法：不能说哪些词；不能被写成哪类通用人设
- 已验证样例：1-3 句短样例，只作校准，不作复制
```

角色声音要能回答三个问题：

- 这个人看见同一件事，第一眼会注意什么？
- 他想达成目的时，习惯用什么说话策略？
- 压力变大时，他的语言会怎么失控或变形？

### 3.7 专有名词与样式表

记录需要长期一致的文字选择。

可记录：

- 人名、别名、外号、尊称、蔑称、错称。
- 地名、组织名、职位名、法宝名、系统名、技能名、副本名。
- 术语拼写、繁简、大小写、连字符、编号格式。
- 章节名规则、卷名规则、时间单位、货币单位、计量单位。
- 内心独白、传讯、弹幕、系统提示、聊天记录、公告、账册等特殊格式。

用法：专有名词一旦进入正文，必须同步进样式表。后续 agent 不得擅自改同义词、改称呼或改格式；如果确实要改，必须写入决策记录或项目台账。

### 3.8 关系称呼与称谓变化

中文网文里，称呼本身就是关系进度条。

可记录：

- 初识称呼、公开称呼、私下称呼、冲突时称呼、亲密后称呼。
- 上下级、师徒、宗门、家族、职场、宫廷、江湖、校园的称谓规则。
- 误称、旧称、故意不用称呼、突然改称呼的剧情含义。

检查问题：如果一个人物突然改称呼，正文是否知道这是关系变化，而不是 AI 随手换词？

### 3.9 可保留的粗糙与缺陷

商业级文本不等于每句话都光滑。某些不完美恰好是声音。

可保留：

- 人物紧张时重复半句。
- 地域、职业、阶层带来的不标准表达。
- 主角视角中的偏见、误判、幼稚、自我辩解。
- 喜剧角色的过度认真、错比喻、坏修辞。
- 情绪场景中的停顿、词穷、绕开正题。

风险：AI 修订最容易把这些都改成“清晰、完整、正确”的句子，结果人物变成说明书。

### 3.10 禁区与不可模仿项

记录本书不该出现的表达。

可记录：

- 禁用句式：频繁“不是 X，而是 Y”、段尾口号、万能顿悟、解释性总结。
- 禁用词气：霸总油腻腔、短视频标题腔、翻译腔、论文腔、古偶空话、职场 PPT 腔。
- 禁用人物处理：所有角色都聪明毒舌、所有人都准确理解主角、所有人都同步震惊。
- 禁用风格模仿：不要复制竞品句子，不要套某作者标志性表达，不要把样例当素材库。

## 4. 角色声音七轴

AI agents 给人物写台词前，先用七轴定位，不要先想口头禅。

| 轴 | 要问的问题 | 错误写法 | 可执行写法 |
| --- | --- | --- | --- |
| 信息优先级 | 他第一眼看什么？ | “他说话冷静” | 先问证据来源、权限、代价或谁在场 |
| 词汇来源 | 他的词从哪里来？ | “古风一点” | 账房说账、医者说脉、修士说因果、主播说节奏 |
| 句子形状 | 他如何组织句子？ | “短句酷” | 紧张时只给结论；撒谎时补很多限定条件 |
| 社交策略 | 他怎么达成目的？ | “会怼人” | 先装糊涂，让对方把关键话说出口 |
| 情绪漏点 | 压力下哪里破功？ | “生气地说” | 突然改敬称、开始算旧账、把话说得过分客气 |
| 回避内容 | 他不愿承认什么？ | “嘴硬” | 不说害怕，只说“流程还没走完” |
| 关系变体 | 他对不同人是否不同？ | “统一人设” | 对上级用规矩，对主角用刺，对下属用命令 |

七轴的目标不是让每句话都花哨，而是让人物在普通信息句里也有自己的判断方式。

## 5. 样例句的使用边界

风格样例有用，但危险。AI 很容易把样例变成复读。

样例使用规则：

- 每个角色只保留 1-3 句短样例。
- 每句样例必须标注功能：威胁、安抚、撒谎、求助、嘴硬、表白、压价、遮掩。
- 样例只校准声音，不允许直接复制进新章节。
- 如果样例来自已发布正文，后续改写不能破坏其事实和关系语境。
- 如果样例来自竞品或外部作品，只能抽象成规则，不得保留可识别句式。

错误用法：

```text
这个角色说话像样例 1，请多写这种句子。
```

正确用法：

```text
这个角色在压力下会变得过度礼貌，先确认流程和见证人，再把对方逼到公开表态。新台词必须保留“礼貌逼迫”的策略，但不能复用原句。
```

## 6. 旁白声音与角色声音要分层

很多 AI 文的问题不是人物台词不对，而是旁白抢了人物的声音。

### 第一人称

旁白就是角色的一部分。记录：

- 这个“我”愿意承认什么，不愿承认什么。
- 这个“我”如何误判别人。
- 这个“我”会用什么词描述世界。
- 这个“我”是否会自嘲、毒舌、嘴硬、装轻松。

风险：第一人称如果过于客观，就像上帝借主角嘴写设定。

### 紧贴第三人称

旁白应被视角人物轻度染色。

执行：

- 描写优先选视角人物会注意的东西。
- 信息解释不能超过视角人物此刻能理解的范围。
- 情绪不直接判词，尽量通过他看见什么、漏掉什么、误读什么呈现。

### 多视角

每个视角人物都需要叙述过滤器。

记录：

- A 视角注意权力和秩序。
- B 视角注意人情和安全。
- C 视角注意钱、效率和漏洞。

如果换视角后只换人名不换观察逻辑，说明视角声音失败。

### 全知或中距离旁白

必须记录旁白规则。

可记录：

- 旁白是否允许幽默。
- 旁白是否允许提前总结人物命运。
- 旁白何时可以解释设定，何时必须让场景证明。
- 旁白是否可以评价人物，还是只陈列后果。

## 7. 对话不是聊天，是带目的的行动

对话要像动作一样改变场面。尤其是移动端阅读里，水对话会快速消耗耐心。

每句对白至少承担一种功能：

- 推进目标：让人物更接近或远离目标。
- 制造阻力：改变对方选择成本。
- 暴露关系：显示谁欠谁、怕谁、瞧不起谁、想保护谁。
- 遮掩信息：说一半，转移焦点，让读者察觉背后有东西。
- 逼迫表态：让对方必须公开选择。
- 改变压力：把私人问题变成公开问题，把小事变成不可退让。
- 提供回报：给读者爽点、笑点、糖点、线索或情绪落点。

删除规则：

- 如果一句对白删掉后，目标、关系、信息、压力都不变，优先删。
- 如果两个人连续三轮只是在确认已知信息，合并或改成行动。
- 如果所有角色都能互换这句台词，回到角色声音七轴重写。

## 8. 多 agent 协作时的声音交接

多个 AI agents 接力写长篇时，风格手册是交接文件，不是装饰文档。

交接前必须提供：

- 当前项目风格手册。
- 当前卷或近 5 章的文本温度变化。
- 主要角色声音卡。
- 已确认称谓、术语和特殊格式。
- 最近新增但尚未完全稳定的候选声音规则。
- 禁止改平的有效表达。

接手 agent 必须做：

- 先读风格手册，再读上一章。
- 如果上一章和风格手册冲突，标出冲突来源，不直接覆盖。
- 起草后输出“风格手册更新项”：新增称呼、术语、声音变化、需要废弃的候选规则。
- 修订时保留角色有效缺陷，不把所有句子修成同一种清楚。

## 9. 声音漂移诊断

出现以下现象时，优先检查风格手册，而不是继续润色句子。

### 人物同声

表现：

- 所有人都说同长度句子。
- 所有人都会精准总结局势。
- 所有人都有同一种幽默感。
- 所有人都使用同一批连接词和抽象词。

修法：给每个角色重新标注信息优先级、词汇来源、社交策略和压力漏点。

### 旁白漂移

表现：

- 古代背景出现现代运营、心理学或职场管理腔。
- 轻松文突然变成严肃评判。
- 爽文高潮被文艺化总结削弱。
- 悬疑文旁白提前解释谜底。

修法：回到叙事距离和词汇层，限制旁白能说什么、不能说什么。

### 口癖泛滥

表现：

- 每个角色都被一个固定词替代。
- 口头禅出现频率太高，变成标签而不是人物。
- 角色只要出场就重复招牌动作。

修法：把口癖改成“策略”。例如不是每次都说“有意思”，而是每次先找到规则漏洞再轻描淡写地试探。

### 修订改平

表现：

- 原本有迟疑、误会、抢话，改后全变成完整说明句。
- 原本有职业/地域/阶层词，改后全是标准普通话书面语。
- 原本有情绪停顿，改后被解释成心理总结。

修法：在风格手册里标注“可保留粗糙”，让修订只解决歧义和无效重复，不消灭声音。

## 10. 审稿时的声音检查

审稿报告中，如果涉及人物或文本执行，必须回答：

- 不看名字，关键人物的台词能否区分？
- 不看章节标题，文本温度是否符合目标平台和题材？
- 旁白有没有泄露角色不该知道的信息？
- 对话是否推动剧情，还是只是聊天和解释？
- 称呼、术语、格式是否前后一致？
- 是否有被 AI 润色抹掉的有效缺陷？
- 新角色是否已经有可记录的声音轴，还是只是功能人？

## 12. 给 AI 的硬约束

- 不能把角色声音简化成口头禅。
- 不能为了通顺抹掉人物的阶层、职业、地域、年龄和压力痕迹。
- 不能让所有角色都用同一套解释性句式。
- 不能复制外部作品或竞品的可识别句子来建立声音。
- 不能把候选风格写成已确认规则。
- 不能在修订时擅自改变称呼、术语和特殊格式。
- 不能让旁白知道角色不该知道的信息，除非项目明确采用全知叙事。
- 不能把风格样例当素材库，只能抽象成声音规则。

## 13. 快速自查问题

- 这本书的整体声音能用 3-5 个可执行词描述吗？
- 旁白能说什么、不能说什么，是否写清？
- 每个重要人物是否有“第一关注点”和“压力漏点”？
- 样例句是否标注了功能，而不是只贴漂亮句子？
- 称呼和术语是否进入样式表？
- 角色声音是否会随关系变化而变化？
- 修订是否保留了有效粗糙，而不是全部改平？
- 新 agent 接手时，能否凭本文续写出同一套叙事选择？

# 106. 命名、称谓、术语与可识别性一致性专项

状态：已确认

适用范围：新书设定、角色命名、群像登场、家族/宗门/公司/组织命名、地名、功法技能名、系统面板、专业术语、古代称谓、亲密关系称呼、外号梗、读者反馈“记不住人”“名字太像”“称呼乱”“术语太多”“设定名像乱码”、多 agent 接力中的改名和术语漂移。

核心结论：名字不是装饰，而是读者识别系统。AI agent 给人物、势力、地点、能力、术语和称谓命名时，必须同时考虑读者记忆负担、类型气质、文化/时代可信度、功能可见性、关系温度、口碑可复述性和长篇样式表一致性。能用功能称呼时，不急着命名；必须命名时，先让读者知道它的作用、关系和后果。

最小链路：命名必要性 -> 读者当前任务 -> 名字预算 -> 功能锚点 -> 音形差异 -> 称谓规则 -> 术语首次绑定动作/后果 -> 样式表回写 -> 后文再识别。

## 1. 为什么需要独立专题

已有第 37 篇管理风格手册和称呼术语样式表，第 78 篇管理信息密度和术语投放，第 87 篇管理角色登场和名字预算，第 100 篇管理正典事实。但命名问题仍值得独立成篇，因为它横跨多个系统：

- 角色名字太多，读者分不清谁是谁。
- 多个名字音形太近，移动端扫读时混淆。
- 同一个角色在不同章节被 AI 改名、改姓、改称谓。
- 古言/玄幻/修仙里称谓、辈分、官职、宗门职位乱用。
- 职业文和行业文堆术语，读者只觉得门槛高。
- 系统文、修仙文、无限流一次性抛出等级名、道具名、技能名、组织名。
- 为了显得原创，生成复杂生僻专名，反而降低可读性。
- 外号和亲昵称呼没有关系变化，只是作者硬发糖或硬搞笑。
- 竞品专名被改几个字就使用，引发融梗和原创风险。

本篇负责把“命名”从灵感行为改为可维护的识别工程。

## 3. 来源吸收与迁移边界

### 3.1 Reedsy / Writer's Digest：角色名要服务类型、文化和记忆

写作资料通常建议：角色名应符合人物背景、时代、文化、类型气质和读者记忆；避免过多相似名字；主要人物的名字应能帮助读者形成印象。

迁移规则：中文网文命名不应只追求好听、生僻或仙气。主角、反派、CP、导师、重要配角的名字要和身份、气质、关系功能、读者记忆标签相配。

### 3.2 PlainLanguage.gov / NN/g：熟悉词和低认知负担更易理解

Plain language 和可用性资料强调：尽量使用读者熟悉的词，避免不必要的行话；界面和文本应支持识别而不是强迫回忆。

迁移规则：专有名词、等级、机构、术语第一次出现时，不应让读者靠背词表理解。先给功能、动作、后果，再给正式名称。

### 3.3 SFWA / 编辑样式表资料：长篇需要 style sheet

编辑和写作资料强调，长篇作品需要样式表记录拼写、人物名、地点、特殊词、大小写、格式和一致性。

迁移规则：多 agent 写长篇时，人名、称谓、外号、地名、组织名、术语、等级名、系统字段和特殊格式必须进入样式表或项目台账。模型记忆不可靠。

### 3.4 起点/番茄和本知识库既有经验：移动端阅读需要名字预算

中文网文移动端阅读节奏快，章节内如果一次投放太多新名字、组织和术语，会直接增加跳读和弃读风险。

迁移规则：单场景新增需要记住的名字默认 1 到 3 个；非关键人物优先用功能称呼，等其产生状态变化或后文复用时再命名。

## 4. 概念定义

### 4.1 正式名

角色、地点、组织、功法、技能、道具、规则或术语在项目 canon 中登记的标准名称。

### 4.2 功能称呼

在读者还不需要记住正式名时，用作用或位置代替名称。

例子：管账的、红甲少年、坐主位的长老、项目负责人、拿钥匙的人、隔壁床的病人。

### 4.3 关系称呼

人物之间基于关系、权力、亲密度、情绪和场合使用的称谓。

例子：师父、师尊、老师、陈总、哥、阿姐、殿下、老谢、那位谢先生。

### 4.4 读者识别名

读者评论和记忆中实际使用的标签或外号。

例子：账本女主、红甲少年、倒霉师兄、那只乌鸦、会拆规则的男主。

### 4.5 样式表名

为了多 agent 一致性而记录的标准用法，包括正式名、别名、禁用写法、首次出现章节、关系称呼和变更条件。

## 5. 命名前的三个问题

AI agent 给任何东西命名前，先问：

1. 读者现在必须记住它吗？
2. 它现在的功能是什么？
3. 后文是否会复用、回响或改变状态？

如果答案是“不必须、不明确、不复用”，暂时不要正式命名。

可先写：

```text
门口那个穿灰色制服的女人没有报名，只把一张空表推到主角面前。
```

不要急着写：

```text
灰衣女子名叫沈璃霜，是天策司第三分署外勤审查组三等巡录。
```

## 6. 名字预算规则

| 场景 | 默认预算 | 说明 |
| --- | --- | --- |
| 单场景新增需要记住的人名 | 1-3 个 | 群像或会议也应分层命名 |
| 单章新增重要角色名 | 1-3 个 | 其他人用功能称呼 |
| 单章新增地名 | 1 个主地点 | 其他地点可用方位或功能 |
| 单章新增组织/势力名 | 1 个 | 必须绑定利益、资源或威胁 |
| 单章新增术语/规则名 | 1-3 个 | 必须绑定动作、风险或后果 |
| 单章新增技能/功法/道具名 | 1-2 个 | 必须马上产生效果或限制 |

超过预算时，必须有群像、战争、组织换卷或重大公开场景理由，并提供视角锚点。

## 7. 好名字的六个条件

### 7.1 可识别

读者扫一眼能和其他名字分开。

检查：

- 是否与已有重要人物同姓、同音、同字形？
- 是否连续出现多个“清、寒、月、霜、云、玄、夜、尘”类相近字？
- 是否有两个角色都叫“小X”“阿X”“老X”，且功能接近？

### 7.2 可承载

名字能承载人物功能、气质、社会位置或类型味，但不要直白到像标签。

风险：反派叫“恶绝天”、女主叫“白纯善”这类过度命名会显廉价，除非是喜剧或讽刺。

### 7.3 可读

移动端读者能顺畅读出，不被生僻字、长串外文、复杂符号和过密标点打断。

原则：生僻字、异体字、长复合名和特殊符号慎用。若必须用，给稳定读法和功能锚点。

### 7.4 可复用

名字、外号或称谓能在后文回响，而不是出现一次就消失。

检查：后文是否会在关系变化、公开评价、口碑传播或情绪回响中再次使用？

### 7.5 可维护

多 agent 不容易写错，样式表能清楚记录。

风险：同一角色有太多别名、尊称、乳名、外号、化名和身份名，会显得丰富，也会让接力写作崩盘。

### 7.6 可原创

不近似竞品专名、影视游戏 IP、现实名人或高识别梗。

涉及相似风险时，调用第 102 篇。

## 8. 不同对象的命名规则

### 8.1 主角名

主角名需要稳定、易记、可反复出现，不宜过度复杂。

检查：

- 是否和书名、主承诺、题材气质不冲突？
- 是否适合读者评论区称呼？
- 是否有自然简称、外号或关系称呼？
- 是否避免与同类爆款主角名过近？

### 8.2 重要配角名

配角名应和功能、阵营、关系和第一印象绑定。

例：

```text
不要只写：陆知遥出场。
推荐：陆知遥把会议室唯一一把备用椅推给主角，自己站到了门边。
```

读者先记住动作，再记名字。

### 8.3 反派/对手名

反派名不能只靠凶狠。更重要的是资源、策略和压迫方式。

检查：读者听到名字时，能否想起“他怎么威胁主角”，而不是只想起“坏人”。

### 8.4 组织/势力名

组织名先给功能，再给全称。

错误：

```text
玄曜天衡司、赤霄内府、九曜执律院同时登场。
```

推荐：

```text
先来的不是宗门的人，而是管刑罚的那一支。弟子们私下叫他们“黑令”。正式名字，等那块黑牌落到桌上时才出现：九曜执律院。
```

### 8.5 地名

地名要服务行动、资源、危险或情绪，不只是地图贴纸。

检查：

- 这个地点有什么功能？
- 到这里会改变信息速度、资源成本、权力关系或风险吗？
- 如果只是临时路过，是否可以用“驿站”“外城”“旧码头”代替正式名？

### 8.6 技能、功法、道具名

名称必须和效果、限制、代价绑定。

不要只写：

```text
主角使出九转玄冥碎星诀。
```

推荐：

```text
他没有硬接，先把灵力压进掌心第三道裂纹。那是“碎星”最危险的用法：能破阵，也会把自己的经脉震出暗伤。
```

读者先知道效果和代价，再记名字。

### 8.7 专业术语

术语必须绑定流程、工具、风险和后果。

如果术语只是炫专业，删掉或换成场景动作。

### 8.8 系统字段和面板名

系统文里，字段越稳定越好。

要求：

- 同一字段不随章节换名。
- 面板字段数量克制。
- 新字段出现要立刻改变选择或风险。
- 系统提示格式进入样式表。

## 9. 称谓矩阵

重要关系必须建立称谓矩阵：

```text
人物 A：
人物 B：
公开称呼：
私下称呼：
冲突时称呼：
亲密时称呼：
疏离时称呼：
身份场合称呼：
禁用称呼：
称呼变化条件：
首次变化章节：
```

### 9.1 称谓是关系温度计

称谓变化要有原因：关系推进、地位变化、背叛、和解、公开承认、私密保护、权力反转或情绪失控。

不要为了发糖突然改称呼，也不要为了虐突然乱改。

### 9.2 场合决定称谓

同一人物在不同场合可以不同称呼，但规则要稳定。

例：

- 朝堂：殿下。
- 私下：阿衡。
- 冲突：太子殿下。
- 心软：衡哥。
- 决裂：姓氏 + 职衔。

### 9.3 禁用称呼同样重要

有些称呼不能用，反而能形成张力。

例：旧爱不再叫乳名，师徒不敢直呼姓名，家族成员故意用官称制造距离。

## 10. 外号和读者梗

外号可以成为口碑资产，但必须来自正文事实。

有效外号来源：

- 角色反复行为。
- 公开事件。
- 关系互动。
- 社群误读。
- 对手羞辱被主角反转。
- 读者评论自发形成。

风险：

- 外号冒犯目标读者。
- 外号只靠作者硬塞。
- 外号复制竞品高识别梗。
- 外号过度消费，变成尬梗。

处理：读者自发外号可作为候选口碑资产，进入第 103 篇台账；正式回收前要检查是否符合人物和价值边界。

## 11. 名字漂移和改名处理

### 11.1 禁止静默改名

同一角色、组织、地点、技能或规则，不能因为 AI 续写时想起不同名字就静默改掉。

发现冲突时：

1. 查样式表和 canon。
2. 确定已确认正式名。
3. 把错误名标为废弃或误写。
4. 若必须剧情内改名，记录变更原因、时间、公开范围和后果。

### 11.2 剧情内改名必须有意义

改名可以成为剧情事件：继承身份、脱离家族、伪装潜入、关系重构、地位变化、公开昭雪。

但改名后需要：

- 正文解释读者为什么要更新记忆。
- 旧名在过渡期继续出现一段时间。
- 样式表记录旧名、现名、别名、使用场合。

## 12. 新名字登场流程

### 12.1 第一次出现

推荐顺序：功能 -> 压力 -> 动作 -> 名字。

```text
管账的人终于抬头。她没看主角，只把账册翻到空白那页：“签这里。”
她叫周映，外城所有租契都要从她手里过。
```

### 12.2 第二次出现

用上次锚点帮读者再识别。

```text
周映又在翻账册。主角这次先看她指尖停在哪一栏。
```

### 12.3 跨多章回归

不要只报名字。至少给一个旧动作、关系、称呼、物件或后果。

```text
周映把那本租契账册放到桌上，封皮比上次多了一道刀痕。
```

## 13. 术语首次出现规则

术语第一次出现，必须至少绑定以下一种：

- 动作：角色做了什么。
- 后果：它改变了什么。
- 风险：误用会怎样。
- 资源：谁能调动它。
- 身份：谁有资格使用。
- 情绪：为什么人物在意。

不要给百科定义。

错误：

```text
灵契是修士与本命灵器之间通过神魂绑定形成的契约体系。
```

推荐：

```text
主角刚碰到剑柄，掌心就被烫出一道细线。旁边的人脸色变了：“别碰，那是灵契。认主的东西，外人碰一下就要赔半条命。”
```

## 15. 审稿检查

### 15.1 命名可读性

- 本章新增需要记住的名字是否超过预算？
- 重要名字之间音形是否过近？
- 是否有生僻字、长串名、复杂专名影响扫读？
- 新名字是否先有功能、动作或关系？
- 是否存在只出现一次但被正式命名的路人？

### 15.2 称谓一致性

- 同一人物对同一对象的称呼是否符合关系阶段和场合？
- 称呼变化是否有剧情原因？
- 是否出现 AI 随机换称谓？
- 关系推进是否能通过称呼变化被读者感知？

### 15.3 术语和专名负担

- 新术语是否绑定动作、后果或风险？
- 专业术语是否只是装饰？
- 系统字段是否稳定？
- 组织名和地名是否有功能？
- 是否需要写入样式表？

### 15.4 原创性风险

- 专名是否近似竞品、影视游戏 IP 或现实机构？
- 是否只是把竞品名称改一个字？
- 是否存在整套命名体系相似？

有风险时，调用第 102 篇。

## 16. 常见错误与修法

| 错误 | 读者体感 | 修法 |
| --- | --- | --- |
| 一章十几个新名字 | 记不住、跳读 | 降到 1-3 个，其余用功能称呼 |
| 名字都很仙/都很酷 | 人物糊成一片 | 拉开音形、气质、身份和功能 |
| 只给名字不给行为 | 像名单 | 先给动作、压力或关系 |
| 称呼随机变化 | 关系线混乱 | 建称谓矩阵和变化条件 |
| 术语堆叠 | 看不懂、像设定表 | 每个术语绑定动作或后果 |
| 生僻字过多 | 移动端卡顿 | 重要名保持可读，生僻字慎用 |
| 地名像地图贴纸 | 世界空 | 地点必须改变资源、风险或关系 |
| 外号硬塞 | 尬梗 | 让外号来自事件和读者复述 |
| AI 静默改名 | 连续性崩 | 查样式表，错误名标废弃 |
| 改竞品专名 | 融梗风险 | 重建命名规则和机制体系 |

## 17. 多 agent 分工

### 17.1 策划 agent

负责：制定命名规则、名字预算、称谓矩阵、术语表和禁用近似名。

### 17.2 起草 agent

负责：按预算投放新名字；第一次出现先给功能和动作；新增正式名后标记回写。

### 17.3 审稿 agent

负责：检查名字混淆、称谓漂移、术语堆叠、样式表缺失和原创性风险。

### 17.4 连续性 agent

负责：维护样式表，处理改名、别名、废弃名和剧情内称谓变化。

### 17.5 包装 agent

负责：检查书名、角色名、势力名和卖点词是否容易被读者复述，是否有竞品近似风险。

## 18. 最小规则

时间很少时，至少执行：

1. 单场景新增需要记住的名字默认 1-3 个。
2. 不重要、不复用的人物优先不命名。
3. 新专名第一次出现先给功能、动作或后果。
4. 重要名字之间必须拉开音形和功能。
5. 同一对象只能有一个正式名，别名和称谓必须登记。
6. 称呼变化必须有关系、场合或情绪原因。
7. 系统字段、技能名、地名、组织名进入样式表。
8. 不用生僻复杂命名证明世界观高级。
9. 不把竞品专名改字后使用。
10. 多 agent 接力前必须读取并更新命名样式表。

# 75. 对话潜台词、战术话轮与高密度台词专项

状态：已确认

适用对象：AI 写作 agent、审稿 agent、人物声音 agent、章节润色 agent、对话重写 agent、群戏 agent。

适用任务：章节起草、对话戏重写、信息交代压缩、人物声音区分、情绪线拉扯、权谋谈判、嘴仗、群戏、公开摊牌、喜剧斗嘴、AI 味诊断、读者反馈为“对话尬”“像问答”“全员同声”“没有潜台词”“台词太直白”的稿件修订。

## 1. 本文解决什么问题

AI 写对话时，经常把对白当作信息运输工具：甲问，乙答；甲解释设定，乙负责惊讶；角色说出自己真实想法，作者省事，读者却感到假。

典型问题：

- 对话像采访问答，一问一答，没有攻防和变化。
- 人物把真实意图、背景、情绪全说出来，没有潜台词。
- 所有人说话节奏、词汇和反应方式一样。
- 台词只传递信息，不改变关系、筹码、压力或行动。
- 每句都接“他说”“她问”，动作拍没有功能。
- 争吵只是互骂，谈判只是解释，暧昧只是互夸。
- 群戏里所有人轮流发言，但没有站队、沉默、插话和权力位移。
- 对话结束后，场景状态没有变化。

本文把 dialogue purpose、subtext、character voice、scene tension、读者补全空间和中文网文对话节奏，整理成 AI agent 可执行的对话设计规则。

## 2. 核心原则：对白是行动，不是聊天复刻

最小链条：

```text
角色目标 -> 台词战术 -> 表层内容 -> 潜台词 -> 对方反应 -> 关系/信息/筹码变化 -> 下一话轮压力
```

写对话前，不先问“他说什么”，而先问：

```text
他说这句话想得到什么？
他说了什么没有说出口？
对方听完后局面变了吗？
```

有效对白至少承担一种功能：

- 推进目标。
- 制造阻力。
- 遮掩信息。
- 试探对方。
- 改变关系距离。
- 争夺解释权。
- 暴露人物价值排序。
- 触发行动或选择。
- 释放爽点、笑点、痛点或暧昧张力。
- 改变场景状态。

如果一句对白删掉后目标、关系、信息、压力和节奏都不变，优先删除或合并。

### 2.1 中文网文对白先像人，再谈战术

本专题的“对白是行动”不能被误用成每一句台词都端着、准着、像设计过。中文网文尤其是校园、轻松、群像、少年小队和生活流场景里，对话允许有毛边：抢话、半句、重复一个词、嘴硬找补、临时改口、用土梗遮尴尬。

自然对白的优先级：

```text
人物会这么说 -> 这个场景能这么说 -> 读者听得懂 -> 有轻微推进 -> 再考虑是否精彩
```

执行规则：

- 熟人之间可以省略主语、结论和解释；不要让他们互相讲彼此都知道的信息。
- 陌生人、同学、上下级、敌对方的边界感不同，不能都用同一种机智吐槽。
- 台词可以不完美，但必须像说话人当下能说出口的东西。
- 口语里的重复、卡顿和找补可以保留，只要它暴露人物或关系，不要机械清理。
- 读者能从上下文分辨说话人时，不必每句都补“某某说”；过多对白标签会显得啰嗦。
- 动作拍不是装饰。人物吃东西、拽袖子、挪盾牌、摸挂件、低头记字，都必须改变节奏、关系或读者对人物的判断。

禁止默认使用：

- 美式吐槽、脱口秀式反讽、影视翻译腔和过度聪明的 punchline。
- 每句都像金句，每个人都能即兴精准接梗。
- 为了“高密度”让角色不说人话。
- 为了“潜台词”把所有人都写成谜语人。

轻松网文的笑点更常来自：

- 人物嘴硬和行动不一致。
- 关系错位：一个人认真，一个人误会，一个人只关心很小的事。
- 现场丢脸和补救。
- 可重复的小癖好在不同场景变形。
- 队友之间逐渐形成的称呼、默认分工和互相拆台。

## 3. 对话话轮的基本单位

一个话轮不是“一句台词”，而是一次攻防。

```text
出招：角色用台词做什么。
接招：对方如何理解、误解、回避或反击。
变局：这轮后筹码、关系、信息或情绪有什么变化。
```

### 3.1 话轮卡

```text
【说话者目标】他想要什么？
【表层台词】他说出口的话是什么？
【真实意图】他真正想达成什么？
【隐藏信息】他不想让对方知道什么？
【战术动作】试探、逼问、示弱、威胁、转移、安抚、嘲讽、交易、求证、拖延。
【对方反应】相信、误解、沉默、反击、装傻、转移、让步、升级。
【状态变化】信息、关系、权力、资源、风险或情绪是否改变？
```

## 4. 潜台词的来源

潜台词不是把话写得玄乎，而是让“说出来的话”和“真实意图/处境/动作”之间出现差距。

### 4.1 说一件事，做另一件事

```text
嘴上说“没事”，手却把杯子往自己这边挪了半寸。
```

适用：压抑、心动、撒谎、恐惧、自尊、关系试探。

### 4.2 只回答安全的一部分

角色避开真正危险的问题，只回答边缘事实。

```text
“你昨晚去哪了？”
“司机送我回来的。”
```

适用：隐瞒、审问、暧昧、权谋、悬疑。

### 4.3 转移话题

话题转移不是水，而是防御动作。

```text
“你还信他？”
“门口那辆车是谁的？”
```

适用：旧伤、背叛、情绪回避、危机现场。

### 4.4 过度礼貌

礼貌可以是刀。

```text
“辛苦您亲自来一趟。”
```

可能潜台词：你本不该来；你来了说明你急了；你已经失去体面。

### 4.5 玩笑遮掩

玩笑不是轻松，而是把真实情绪包起来。

```text
“放心，我命硬，阎王排队都排不到我。”
```

可能潜台词：我怕，但我不能让你怕。

### 4.6 称呼变化

称呼是关系温度计。

- 全名：拉开距离、警告、正式化。
- 小名：亲密、操控、旧关系召回。
- 职位：权力、冷淡、场合压力。
- 不称呼：回避、失望、关系空洞。

### 4.7 沉默和未完成句

沉默必须有功能。

有效沉默：

- 对方说中了。
- 角色在权衡代价。
- 角色决定不解释。
- 角色把主动权让出去。
- 角色被情绪卡住。
- 沉默本身被旁观者理解成态度。

无效沉默：只是为了装深沉。

## 5. 台词战术库

| 战术 | 表层表现 | 真实功能 | 风险 |
|---|---|---|---|
| 试探 | 问一个看似无关的问题 | 看对方是否知道、在乎或撒谎 | 问题太直会像审讯稿 |
| 逼问 | 连续追问关键点 | 压缩对方回避空间 | 过长会像作者查户口 |
| 示弱 | 承认一部分弱点 | 换信任、引诱对方放松 | 不能每次都假弱 |
| 威胁 | 点出后果 | 改变对方成本计算 | 只喊狠话会廉价 |
| 转移 | 换话题 | 避开痛点或拖时间 | 需要让读者看出不自然 |
| 安抚 | 降低对方防备 | 稳住关系或换取行动窗口 | 不能变成空泛鸡汤 |
| 嘲讽 | 攻击面子 | 引出对方失误或反应 | 连续嘲讽会变吵闹 |
| 交易 | 给条件 | 改变资源和利益结构 | 条件必须具体 |
| 求证 | 让对方确认细节 | 固化证据或制造回看线索 | 太明示会剧透 |
| 拖延 | 说无关内容 | 等援手、等证据、等情绪冷却 | 需有时间压力 |
| 抢解释权 | 先定义事件 | 影响旁观者理解 | 需联动信息战规则 |
| 留白 | 说到一半停住 | 让读者和对方补全 | 留白过多会谜语人 |

## 6. 不同类型对话的写法

### 6.1 信息交代型对话

目标：让信息进入场景，但不变成说明书。

可用链条：

```text
角色需要行动 -> 缺少某信息 -> 通过冲突问出/逼出/误读信息 -> 信息改变选择
```

规则：

- 不要让角色讲彼此都知道的背景。
- 信息必须影响下一步行动。
- 让信息带着偏见、立场或隐瞒出来。
- 关键设定优先通过代价、限制、例外和选择体现。

### 6.2 争吵型对话

目标：不是谁骂赢，而是谁暴露真实在乎的东西。

可用链条：

```text
表层争点 -> 旧账/恐惧被触碰 -> 话术升级 -> 失控或收住 -> 关系状态改变
```

规则：

- 争吵不能只重复“你错了”。
- 每次升级都要换攻击点：事实、动机、关系、旧伤、未来后果。
- 最重的一句不要太早出现。
- 争吵后必须有关系后果：冷战、欠账、道歉条件、边界或决裂。

### 6.3 谈判型对话

目标：改变资源、条件、站队或权力位置。

可用链条：

```text
开价 -> 试探底线 -> 暴露筹码 -> 对方反制 -> 新条件 -> 临时结果
```

规则：

- 每个人都要有底线和可交换筹码。
- 不要让谈判只是主角长篇说服。
- 条件必须具体，不能只说“你帮我”。
- 谈判结果要改变后续行动资格。

### 6.4 暧昧和情绪拉扯对话

目标：让关系距离发生微变化。

可用链条：

```text
安全话题 -> 越界细节 -> 回避/玩笑 -> 试探回应 -> 关系距离变化
```

规则：

- 不要只互夸和发糖。
- 心动要有选择压力、误读或边界变化。
- 亲密不一定靠直白告白，可以靠称呼、停顿、记得小事、替对方留退路。
- 女频情绪线必须保护选择权，不要用对话逼迫原谅。

### 6.5 嘴仗和公开摊牌

目标：让关键受众改变理解或行动。

可用链条：

```text
争点定义 -> 对手叙事 -> 主角拆点 -> 证据落地 -> 旁观者站队变化 -> 余波
```

规则：

- 嘴仗不能只比谁嗓门大。
- 每句台词要服务争点、证据、受众或行动请求。
- 旁观者不能无利益变化就集体倒戈。
- 公开对话要联动合规和信息战规则。

### 6.6 喜剧斗嘴

目标：让笑点服务人物、关系或剧情。

可用链条：

```text
角色癖好 -> 误读/错位 -> 回嘴 -> 反应升级 -> 小后果
```

规则：

- 包袱来自人物，不是作者硬塞段子。
- 重复梗要有变体和后果。
- 斗嘴不能让角色持续降智。
- 轻松对话结束后也要有关系、信息或行动微变化。

### 6.7 群戏对话

目标：让多个角色按身份、利益、信息差分层反应。

可用顺序：

```text
权力最高者定调 -> 直接受损者抢话 -> 利益相关者试探 -> 情绪外露者打断 -> 沉默者给关键动作 -> 主角选择
```

规则：

- 群戏不是轮流报台词。
- 每个人只说符合其利益和信息权限的话。
- 沉默、眼神、站位和抢话同样是话轮。
- 群戏中至少要有一个人说错、避开或误读，才有人味。

## 7. 对话密度和移动端节奏

中文网文对话可以短、快、密，但不能空。

### 7.1 快对话适合

- 争吵、打脸、追问、喜剧斗嘴、危险现场。
- 每句都改变压力或节奏。
- 读者能从上下文识别说话者。

### 7.2 慢对话适合

- 情绪承认、谈判、告别、旧伤揭露、重大选择前。
- 需要动作拍、沉默、环境反馈和身体反应承压。

### 7.3 长台词使用条件

长台词必须满足至少两个条件：

- 角色有权说这么久。
- 对方暂时不能打断。
- 内容改变局面。
- 语言体现角色身份和价值排序。
- 长台词内部有转折，而不是平铺解释。
- 说完后有明确反应和后果。

## 8. 动作拍和对白标签

动作拍不是为了替代“他说”，而是为了显示话术外的真实反应。

动作拍适合出现于：

- 台词与真实情绪不一致。
- 一方试探，另一方需要防御。
- 关系距离改变。
- 谎言、隐瞒、旧伤被触碰。
- 说话者抢回主动权。
- 对话需要降速。

动作拍风险：

- 每句都配动作，会显得机械。
- 动作只写“抬头、看着、皱眉、沉默”，会失去功能。
- 花哨说话动词不能替代台词本身的力量。

优先使用：短动作、站位、物件、停顿、称呼变化、未完成句。

## 9. AI 对话修订流程

第一遍：删水对白。

- 删除寒暄、重复确认、双方都知道的信息。
- 删除不改变目标、关系、信息、压力的句子。
- 合并连续同义台词。

第二遍：补战术。

- 给每个说话者标注本场目标。
- 给关键台词标注试探、威胁、遮掩、交易、安抚、求证等功能。
- 让每一轮对话至少改变一点局面。

第三遍：补潜台词。

- 把直白情绪改成动作、话题转移、称呼变化或半句没说完。
- 让角色只说对自己安全的那部分。
- 保留必要直说，不要把所有台词都写成谜语。

第四遍：分声音。

- 调整词汇、句长、逻辑顺序、攻击方式、幽默方式、避让方式。
- 检查角色是否都像同一个作者在说话。

第五遍：接后果。

- 对话结束后，记录关系、信息、筹码、目标或风险变化。
- 如果没有变化，压缩或删除这段对话。

## 10. AI 常见失败与修复

| 失败表现 | 读者体感 | 修复方法 |
|---|---|---|
| 采访式问答 | 像作者借角色解释 | 给双方各自目标和隐瞒，让问题带压力 |
| 全员同声 | 人物像同一个 AI | 调整词汇、句长、逻辑顺序和防御方式 |
| 台词太直白 | 没潜台词 | 改成只说安全部分、转移话题或动作泄露 |
| 争吵重复 | 吵但不推进 | 每轮升级换攻击点，并产生关系后果 |
| 长台词说明书 | 想跳读 | 拆成冲突问答、证据、行动和反应 |
| 动作拍机械 | 像摆姿势 | 只在情绪矛盾、关系变化和试探处使用 |
| 沉默滥用 | 装深沉 | 给沉默明确功能：承认、拒绝、权衡、让权 |
| 群戏轮流发言 | 像会议纪要 | 按身份、利益、信息差安排抢话、站队、沉默 |
| 暧昧只互夸 | 糖很假 | 加边界、误读、选择压力和关系微变化 |
| 对话后无变化 | 水对白 | 检查状态增量，压缩或删除无功能对话 |

## 11. 审稿检查清单

逐段检查：

- 这段对话中，每个人想得到什么？
- 每句关键台词是否有战术功能？
- 是否有角色说出了彼此都知道的信息？
- 潜台词来自隐瞒、转移、动作、称呼、沉默还是语气反差？
- 对话是否改变目标、关系、信息、筹码、风险或情绪？
- 如果删除某句，局面是否不变？若不变，是否应删？
- 角色声音是否能通过词汇、句长、节奏和防御方式区分？
- 动作拍是否有功能，而不是机械插入？
- 长台词是否有权力条件、内部转折和说完后的后果？
- 群戏是否避免轮流发言和全员同步理解？

## 12. 与其他文档的配合方式

## 13. 最小执行规则

1. 对白不是现实聊天复刻，也不是战术表演；它首先要像这个人此刻会说的话。
2. 每段对话至少让读者获得一种增量：人物、关系、气氛、信息、压力、梗点、节奏缓冲或行动变化。
3. 关键台词要有战术功能：试探、逼问、遮掩、交易、安抚、威胁、求证、转移或抢解释权。
4. 潜台词来自说话和真实意图之间的差距，不来自故意谜语人。
5. 角色不能把彼此都知道的信息讲给对方听。
6. 沉默、动作、称呼变化和话题转移必须有功能。
7. 长台词必须有权力条件、内部转折和后果。
8. 群戏对话按身份、利益、信息差分层反应，不轮流报台词。
9. 情绪线对话要保护选择权和边界，不能用台词逼迫原谅。
10. 对话修订先判断声音和关系是否自然，再删水、补战术、补潜台词，最后接后果；不要为了显得高级把普通人话改成编辑腔。

## 14. 来源与吸收方式

外部来源主要提供四类启发：

- Reedsy 对 dialogue 的写作建议：对白应推动故事、塑造人物动态、控制节奏，并通过修订删除无功能内容。
- Writer's Digest 关于 dialogue rules 和 subtext 的资料：对话不是单纯表达信息，而是角色克服阻力的方式；潜台词可以通过偏题、细枝末节、动作和语境制造。
- Helping Writers Become Authors 关于 subtext 的资料：读者需要参与补全，作者不必把所有意义都说穿。
- 起点社区关于对话小说写作的资料：中文网文语境中，每一句对白都应踩在剧情上，拒绝日常流水账式水对话。

本文未照搬来源原文，而是将这些原则改写为中文商业网文 AI agent 可执行的“战术话轮”系统：角色带目标开口，用台词试探、遮掩、交易、攻击或安抚，对方反应后必须改变关系、信息、筹码、压力或情绪状态。

# Stage 6：文风档案生成与单独重建

完整管道收尾或单独补缺失的 `文风.md` 时读本文件。单独补文风不触发 Stage 1–5。`拆文库/{书名}/文风.md` 由本 skill 独占写入；书被选为另一项目的对标时，由 story-import 或 story-long-write 首次引用时复制到 `{项目}/对标/{书名}/文风.md`。

## 原则

1. 文风档案描述作者实际写法，不评价作者水平。
2. 情绪和节奏意图以 `剧情/情绪模块.md`、`剧情/节奏.md` 为准，文风只管表达层。
3. 已有完整 `文风.md` 时原样保留；用户明确要求增强时才更新。
4. Stage 6 不重扫全书，只允许按索引行号定点回读 4–6 段原文。
5. 摘要措辞不能冒充作者原句；缺少原文和有效样本时报错。

## 来源顺序

1. 既有 `文风.md`；
2. 项目内非空且含连续原文的 `_style-sample.txt`；
3. `章节/第1章_深度拆解.md`–`第3章_深度拆解.md` 中带定位的短引和写法证据；
4. `_analysis_cache/批次-*.md`、`章节/*_摘要.md` 与 `拆文报告.md` 的结构层观察；
5. 仍缺锚点时，读 `chapter_index.csv`，按“覆盖主要基调”选 4–6 章，再按 `start_line/end_line` 定点读原文片段。

旧项目缺索引时可单独建索引，不写 `_progress.md` 或启动其他阶段。

## 单独重建文风

当 story-long-write 或用户发现 `文风.md` 缺失时：

1. 运行检查器，确认其他拆文成果可用且 `stage_repairs` 包含 `stage6_style` 或 `stage6`；
2. `_style-sample.txt` 有效就直接用；
3. 样本不足时确认 `chapter_index.csv` 与原文存在。缺索引时只运行：

   ```text
   "{PYTHON}" "{story-long-analyze skill 根}/scripts/build_chapter_index.py" --source "{拆文目录}/原文/原文.txt" --output "{拆文目录}/chapter_index.csv" --locator-path "原文/原文.txt"
   ```

4. 从索引选 4–6 章，覆盖已有资料能确认的不同基调；每章按行号取一段 300–500 字连续原句，写入或更新 `_style-sample.txt`；
5. 按下方模板生成 `文风.md`；
6. 落盘后运行：

   ```text
   "{PYTHON}" "{story-long-analyze skill 根}/scripts/manage_analysis_run.py" mark-stage --root "{拆文目录}" --stage stage6 --output "文风.md"
   ```

索引、原文和有效样本都不存在时停止，返回“无法取得可验证文风锚点”，不得生成锚点全空的可用文风。

## 报告回填

完整管道或续跑中，文风落盘后、标记 `stage6` 前，检查 `_progress.md` 受管阶段表：`stage5` 为 `completed`、产物为 `拆文报告.md`，且报告「文风一句话」仍待补时，用 `文风.md` 补齐该段。已有简述保留；单独补旧项目文风不改已有报告。

## 篇幅与可信度

总上限 4000 字：描述部分（整体语感、对话技法、情绪交替模式、可借鉴技巧、分层模仿建议）≤1800 字，原文锚点 4–6 段、每段 300–500 字、合计 ≤2100 字，生成记录与不建议模仿合计 ≤100 字。

每项结论后写一行「依据」，用下面三种说法之一：

| 依据 | 什么时候写 |
|---|---|
| 已有资料 | 从既有拆文成果读出，如章基调序列从逐章摘要的基调行统计 |
| 原文锚点 | 从 4–6 段原文锚点归纳，锚点覆盖三种以上基调 |
| 样本不足 | 锚点不到 4 段、只覆盖一两种基调，或只能依据摘要措辞 |

## character-profiles

# 人物设定

## 存放与结构
设定集/人物 是固定目录，不能改名或删除。每人一个 JSON，文件名使用人物名（主角访谈使用 主角.json），不要为同一人物重复建档。旧 Markdown 仅供兼容阅读；新增人物不得使用 Markdown。
JSON 外层固定为 schemaVersion: 1 与 fields 对象。程序以两个空格缩进格式化保存，禁止通过 workspace.save、stagingPromote、文本替换、bash 或脚本直接编辑 JSON。

推荐 fields 字段：姓名、身份、性格爱好、样貌、年龄、身世背景、目标、能力、人物关系、其他信息、备注。未确定值留空，不编造已确认事实。年龄可用字符串表达；关系可为对象或列表。
允许根据剧情新增、删除、更改 fields 内的字段，包括自定义字段，值可为字符串、数字、布尔值、null、数组或对象。不允许变更外层结构或 schemaVersion。

## AI 操作
先读取已有 JSON 与本规则。使用 character_update 工具：首次 describe 获取参数，然后 invoke。创建 mode=create，更新 mode=update；relativePath 为 设定集/人物/姓名.json；operations 为字段操作列表。
set 操作示例：{"op":"set","field":"所属阵营","value":"观星社"}；delete 操作示例：{"op":"delete","field":"旧称号"}。不传完整 JSON 文本，不使用 markdown 参数。修改嵌套资料时先读取该字段，再仅提交该字段的新值；保留其他内容。读取结果中的 content 可作为 expectedContent 提示基线；若磁盘已有更新，服务端会按写入锁顺序重读最新内容后再叠加本次操作，不会因并发直接失败。

## batch-volume-deduction-plan

# 批量推演规划（卷粒度）

本文档供创作台 Agent 使用（平台规则投影）。**不要向用户展示操作入口**；由你判断时机后，在回复中用 `choices` 给出「开始批量推演」「按章推演」两个按钮。

## 目标

- **最小批量粒度 = 一卷**：从第一卷起，按「尚未完成正文链路的卷」一卷一卷推。
- **卷大纲是硬门槛**：目标卷没有合格卷大纲时，禁止开启批量推演；应先帮用户把大纲补齐。
- **作品风格是硬门槛（更靠前）**：开书须先 `choices` 给出 2–3 套风格备选（**每套绑定一个** `表现输出/笔风规则/*.md`，并含命名规则与对话方式），再把 `表现输出/本作品描写/作品风格.md` 的 **1→8 维全部定好写入**（语体笔风须点名笔风路径；命名须正反例；句子与对话须含对白系统）。未落盘、缺维、仍为「待定」或实质不足时，禁止卷大纲确认后的批量/正文；不得用一串「禁止」代替八维正向定义。
- **推演模式二选一**（风格 + 卷大纲均就绪后，用互斥 `choices` 询问用户）：
  - **开始批量推演**：整卷后台连续推；讨论区展示进度列表；未点停止则继续；可暂停/继续。
  - **按章推演**：只推当前焦点章全链路后停止。

## 路径（代码约定）

- 本规则：`世界推演规则/基础规则/batch-volume-deduction-plan.md`
- 卷大纲：`大纲/{卷文件夹名}.md`
  - 例：`大纲/第一卷 开局即仇敌.md`
  - **`{卷文件夹名}` 必须与 `章节正文/{卷文件夹名}/` 完全一致**

## 合格卷大纲（准入）

1. 文件存在且非空；
2. 含卷目标 / 冲突主线的总述；
3. 至少列出 **2 个章节点**；
4. 每章有一句以上目的或事件锚点。

用户可只给一句话或一段素材；你必须主动完善并写入 `大纲/{卷名}.md`，再给出推演选项。

## 批量阶段（系统编排）

1. **卷规划**（`【批量推演·卷规划】`）：必须给出 `volumePlanMeta.targetChapterCount` 和 `targetWordCount`，用 `volumeChapterPlans` 写齐目标范围内每章梗概+细纲。系统持久保存目标章数并按 `已完成/N` 展示；N 是强制停止门槛。
2. **正文草稿**（默认）：同一次回复用 `chapterDraftProposals` 写多章草稿；**禁止优先** `chapter_workflow`；勿 `publish_draft`。缺草稿时按章补写。
3. **可选正文推演**：仅当项目设置启用「正文推演工具」时，系统可走 `chapter_workflow`（可带 `chapterSequences`）一次多章草稿。
4. **图治理**：系统按章节序号**串行** `submitRevision`，等一章图同步完成再下一章；目标内所有章节均完成图修订后才能停止。AI 调整章数时重新输出 `volumePlanMeta.targetChapterCount`，系统按新目标更新进度与章节范围。

## 思维链（讨论时按序推进）

1. **定位卷**：从第一卷起，找第一本「尚有章节未完成正文」的卷。
2. **读/建作品风格**：`list`/`request_read` `表现输出/本作品描写/` 与 `表现输出/笔风规则/`；若无 `作品风格.md` 或 1–8 维未全部定好（含人称指称、句子与对话），先风格备选 `choices` 再 `presentationWrites` 写全落盘，再往下。
3. **读卷大纲**：`request_read` `大纲/{该卷}.md`（可先 `list` `大纲/`）。
4. **缺口则完善**：风格合格后写入卷大纲；勿声称可以批量。
5. **风格+大纲就绪 → 模式选择**：`choices` 仅给「开始批量推演」与「按章推演」（可另给「再改大纲」）；界面不另设常驻按钮。
6. **批量进行中**：少打扰；系统会展示章节进度（规划/草稿/正文）；**禁止** `set_focus` / `focusChange`。
7. **暂停后**：用户可改设定；继续时从暂停章接着推。

## 禁区

- 作品风格未落盘，或 1–8 维未全部定好写入本作品描写时，写卷大纲/正文或诱导批量推演。
- 卷大纲未合格时诱导批量推演。
- 批量中输出 `set_focus` / `focusChange` 或要求用户逐章点确认。
- 默认路径下优先 `chapter_workflow` 或自行 `publish_draft`。
- 把 `暂存区/弧线规划.md` 当成卷大纲唯一来源——卷大纲以 `大纲/{卷名}.md` 为准。


## 开书卷规划首次写入门禁（优先于本文其他批量规划说明）

完整顺序固定为：用户输入构思 → AI 评估并由用户选择风格 → 当前卷规划讨论 → 本卷第一章剧情梗概 → 剧情细纲 → 草稿 → 审核 → 图修订 → 正文 → 后续章节 → 下一卷规划。

在第一章之前，必须先确定本卷目标章节数与预计总字数，并分别首次写入卷梗概和卷大纲。结构化输出使用 `volumePlanMeta`、`volumeSynopsis.markdown`、`arcPlan.markdown`：卷梗概写入 `大纲/{卷名}.梗概.md`，卷大纲写入 `大纲/{卷名}.md`。只有系统持久状态记录两个文档都成功首次写入，才能在下一轮进入第一章。仅文件存在或非空不构成门禁状态。

卷信息面板显示目标章节进度 `x/N`、已有字数/预计字数、卷梗概与卷大纲写入次数。后续用户或 AI 都可调整目标、梗概和大纲；首次写入门禁通过后，不得要求重复首次写入。每卷完成规划的目标章节正文链路后，才开始下一卷的卷规划。
